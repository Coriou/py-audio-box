# Commercial voice products and agent integration audit

Evidence date: **2026-10-15**. Compared against the current `PLAN.md` after Astra R2. Research only: public official documentation and vendor-owned repositories were inspected. No accounts, installs, authentication, paid requests, synthesis, listening tests or running MCP connections. “Documented” below means the vendor describes the feature; it does not establish acoustic quality, reliability, account eligibility or actual client compatibility. Prices, latency rankings and subjective quality rankings are deliberately omitted.

## Finding

The plan already addresses the difficult infrastructure issues: one authoritative store, immutable plans, supervised workers, revision-safe human/agent editing, compact discovery, bounded jobs and independent completion delivery. The largest omissions exposed by existing products are **pronunciation and spoken-text preparation, continuity between regenerated passages, explicit performance direction, acceptance/locking of takes, and actionable quality review**.

These are product and contract lessons. They do **not** imply adding paid providers. A self-hosted engine may lack a commercial model capability; the interface should expose that honestly and preserve the data needed to support it later. A timeline, durable queue or MCP wrapper cannot create missing model capabilities.

## Current status matters

* **Resemble is a historical hosted-voice precedent, not a confirmed current commercial voice candidate.** Its official Voice AI Research Archive says generative voice models are no longer offered as commercial paid products; old hosted API documentation is retained for reference. Open Chatterbox research is a separate subject. [Resemble archive notice](https://docs.resemble.ai/voice-archive).
* **ElevenLabs has several different agent surfaces.** Its old `elevenlabs-mcp` repository is archived, while current documentation describes a hosted OAuth MCP server for managing ElevenAgents. The current official coding-agent plugin additionally says its hosted MCP includes TTS. This is a documentation-surface distinction to verify through a permitted future connection, not proof that every creative studio action is callable. [Archived repository metadata](https://github.com/elevenlabs/elevenlabs-mcp/blob/main/server.json), [hosted MCP](https://elevenlabs.io/docs/eleven-agents/operate/hosted-mcp), [current official plugin](https://github.com/elevenlabs/plugin).
* The examined Hume docs describe capability differences between Octave versions. Cartesia's current MCP docs name API revision `2026-08-14`. These are moving product surfaces; avoid transplanting older examples as a universal contract. [Hume voice compatibility](https://dev.hume.ai/voice/docs/text-to-speech-tts/voice), [Cartesia MCP](https://docs.cartesia.ai/tools/ai/mcp).

## 1. ElevenLabs: production work is more than a TTS call

The current Studio guide describes a script/timeline workflow with paragraph-level generation history, paragraph locks, chapters, Actor Mode, imported or generated supporting audio, and new export versions after edits. It also documents an AI co-editor for video projects, with plan/create modes; that co-editor is explicitly unavailable through the API. The lesson is to preserve editable production state and inspectable change proposals, while avoiding an unsupported promise of UI/API parity. [Studio guide](https://elevenlabs.io/docs/eleven-creative/products/studio).

Audiobooks adds character casting and project pronunciation dictionaries. Its dictionary notes specify first-match ordering, regeneration after dictionary changes and limited phoneme/model support. Casting is a useful optional assisted workflow, but should produce a reviewable speaker map, not rewrite a supplied manuscript silently. [Audiobooks guide](https://elevenlabs.io/docs/eleven-creative/products/audiobooks).

Voice Design creates previews and then saves a selected preview as a named voice. Remixing starts from a permitted existing voice and a description, then saves a new voice. These workflows separate exploring candidates from mutating a production identity. [Voice Design](https://elevenlabs.io/docs/eleven-api/guides/how-to/voices/voice-design), [Voice Remixing](https://elevenlabs.io/docs/eleven-api/guides/how-to/voices/remix-a-voice). Text to Dialogue accepts an ordered list of text/voice pairs; its existence supports retaining dialogue structure, rather than flattening a scene into independent unrelated strings. [Dialogue API](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert).

Instant cloning uploads audio samples and returns a voice ID. Professional cloning has a longer sample-management/preparation workflow, including speaker separation for multi-speaker material. These are different preparation modes, not merely two quality labels on an already ready voice. [Instant cloning](https://elevenlabs.io/docs/eleven-api/guides/how-to/voices/instant-voice-cloning), [professional cloning](https://elevenlabs.io/docs/eleven-api/guides/how-to/voices/professional-voice-cloning).

Request stitching can condition one generation on previous request IDs; those earlier requests must have finished, IDs have a documented freshness window, and `eleven_v3` is excluded. This is a model- and service-specific continuity mechanism, not proof that independently cached blocks will always join naturally. [Stitching guide](https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/request-stitching). The dictionary guide passes both dictionary ID and version ID, a particularly useful provenance convention. [Dictionary API example](https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/pronunciation-dictionaries).

The separate Auto-Regenerate help page describes bounded quality checks and retries for bulk conversion. This is a useful workflow precedent; our implementation should expose QA findings, retries and selection policy rather than copying automatic replacement invisibly. [Auto-Regenerate](https://elevenlabs.io/docs/help-center/product/studio/studio/what-is-auto-regenerate).

API keys can have endpoint scopes, credit limits and expiry; service-account and personal credentials have different lifecycles. This is stronger than merely showing a usage counter. [API key controls](https://elevenlabs.io/docs/overview/administration/workspaces/api-keys). Current webhook documentation covers specific events and bounded delivery policies; it is not evidence that every TTS request has a completion callback. [Webhook event and retry contract](https://elevenlabs.io/docs/eleven-api/resources/webhooks).

For discoverability, the CLI can generate command-group skills from its embedded API definition without credentials, keeping the instructions tied to the installed version. That is a good precedent for short generated adapter documentation and offline schema/help. [ElevenLabs CLI](https://elevenlabs.io/docs/eleven-agents/operate/cli). The official agent tooling guide separately distinguishes SDK-oriented skills and hosted agent-management MCP. [Agent tooling](https://elevenlabs.io/docs/eleven-api/resources/agent-tooling).

## 2. Cartesia: clear transport and artifact semantics

Cartesia's instant clone documentation ties sample constraints to model versions and explains that reference mood, accent and pacing influence the clone. It distinguishes instant from professional cloning and describes language/accent adaptation separately. “Voice ready” should therefore mean ready for a capability/language, with an audition sample, not merely “an ID was created.” [Instant clone guide](https://docs.cartesia.ai/build-with-cartesia/capability-guides/clone-voices). The control guide exposes speed, volume and emotion through explicit generation configuration and supported tags. [Voice controls](https://docs.cartesia.ai/build-with-cartesia/capability-guides/volume-speed-emotion).

Dictionaries support phonetic or sounds-like replacements and model-specific case matching/collision rules. This illustrates why pronunciation needs explicit locale, matching semantics, validation and version identity. [Custom pronunciations](https://docs.cartesia.ai/build-with-cartesia/capability-guides/custom-pronunciations).

Its transport comparison is unusually useful: bytes, SSE and WebSocket all stream audio, but timestamps and input continuation differ. An HTTP `context_id` does not merge separate requests; WebSocket contexts group partial text into an utterance. Wire framing and durable jobs are independent decisions. [Endpoint comparison](https://docs.cartesia.ai/use-the-api/compare-tts-endpoints). Flush IDs mark transcript boundaries within a continuing context. [Flush IDs](https://docs.cartesia.ai/api-reference/tts/working-with-web-sockets/context-flushing-and-flush-i-ds). An official infill example accepts left/right audio and replacement text, demonstrating a stronger future “repair this passage” capability than regenerating a whole paragraph. The example uses a specific model; no seamless quality claim was tested. [Infill example](https://docs.cartesia.ai/examples/infill-create).

Hosted MCP documentation distinguishes `file_id`, local `file_path` and expiring `download_url`; a laptop path is not a hosted-server path. TTS persists a cloud result by default, and download can refresh a link. Tools cover filtered voice lookup, cloning/localization, dictionaries and administrative usage lookup. This is a strong example of small composable handles; persistence and disclosure defaults must remain explicit in our self-hosted product. [MCP contract](https://docs.cartesia.ai/tools/ai/mcp).

Its agent guide offers a lightweight capability summary and `llms.txt`, treats skills and MCP as optional additions and keeps SDKs as production integration. Copy the progressive discovery principle; do not require installing a plugin to read a capability summary. [Agent guide](https://docs.cartesia.ai/tools/ai/agent-guide).

## 3. Hume: identity, performance and context are separate controls

Voice design combines an identity description and example text; reusable voice creation is distinct from performing a line. Current docs require Octave 1 for design, while permitting those voices in Octave 2. [Voice Design](https://dev.hume.ai/voice/docs/voice/voice-design). Cloning accepts microphone recording or uploaded speech, subject to access limits. [Voice Cloning](https://dev.hume.ai/voice/docs/voice/voice-cloning).

Acting instructions are separate from the spoken text. The current guide limits `description` to Octave 1, while speed and trailing silence work across models. A generic “emotion supported” flag would hide this incompatibility. [Acting instructions](https://dev.hume.ai/voice/docs/text-to-speech-tts/acting-instructions). Continuation uses an immediate prior utterance or generation/context reference; reference-only context is not itself synthesized. This argues for keeping direction and continuity metadata outside authored text. [Continuation guide](https://dev.hume.ai/voice/docs/text-to-speech-tts/continuation).

The JSON synthesis schema includes multiple utterances, candidate-generation count, model version and a request ID. Its result includes encoded audio, which should be stored outside the model's context in our adapter. Streaming/instant mode has additional constraints; an async SDK function must not be mistaken for a durable asynchronous job. [Synthesis schema](https://dev.hume.ai/voice/reference/text-to-speech-tts/synthesize-json), [streamed schema](https://dev.hume.ai/reference/text-to-speech-tts/synthesize-json-streaming?explorer=true).

The MCP server offers TTS, replay by generation ID, voice listing, save and delete. Its documented defaults include WAV output, optional embedded audio, `strip_headers=true`, and a larger voice-list page size than the underlying API. Replay/save handles are useful; invisible stripping and broad lists are not good defaults for exact-copy, compact-context workflows. [Hume MCP](https://dev.hume.ai/voice/docs/integrations/mcp). Error codes distinguish exhausted credits, credit cap and rate limiting; those categories warrant different remediation. They do not establish a user-configurable per-job hard ceiling. [Errors](https://dev.hume.ai/voice/docs/resources/errors).

No durable TTS submission/poll/callback lifecycle or managed pronunciation dictionary was established in the examined Hume TTS sources. EVI conversational webhooks/resume are a different product surface and should not be borrowed as evidence for production TTS jobs.

## 4. Azure and MiniMax: useful batch precedents

Azure's Audio Content Creation tool authors speech through SSML and lets an operator audition pronunciation, style and prosody before exporting or reusing the instructions in SDK/CLI workflows. [Authoring tool](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-audio-content-creation). SSML supports voice/language/style, pronunciation lexicons, prosody and other controls, with voice-specific support. It is an interchange/control vocabulary to learn from, not a requirement to expose raw XML everywhere. [SSML overview](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup).

Azure's batch service has explicit create/get/list/delete operations and polling-based result retrieval. Its separate properties document exposes per-input success/failure counts, billing details, concatenation, retention and word/sentence boundary sidecars. These are good patterns for partial outcomes, usage accounting and timing provenance. No general webhook/wakeup guarantee follows. [Batch lifecycle](https://learn.microsoft.com/azure/ai-services/speech-service/batch-synthesis), [batch properties](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/batch-synthesis-properties).

MiniMax's long-TTS guide accepts text or an uploaded text-file ID, returns a task ID, then an output file ID. It describes subtitle timing and explicit output expiry. The important lesson is to distinguish job, file and temporary delivery grant, and to import outputs before an external grant expires. [Long-TTS workflow](https://platform.minimax.io/docs/guides/speech-t2a-async). The query reference describes processing/success/failure/expiry states, but contains differently cased example versus enum spellings: generated snippets still require conformance tests. [Task query](https://platform.minimax.io/docs/api-reference/speech-t2a-async-query).

Voice Design uses separate identity prompt and preview text, returning a voice ID and audition audio. [Voice Design](https://platform.minimax.io/docs/api-reference/voice-design-design). Official MCP tooling supports speech and cloning; its guide now recommends CLI for simpler use. This reinforces offering both compact CLI and MCP rather than treating one protocol as the whole product. [MCP guide](https://platform.minimax.io/docs/guides/mcp-guide).

## 5. Resemble: retain lessons without treating archives as availability

The archived clip object separates project, clip, voice, synthesized text, duration and character/phoneme timestamps. [Former clip model](https://docs.resemble.ai/platform-management/clips), [timestamp contract](https://docs.resemble.ai/platform-management/clips/timestamps). The still-published Node SDK examples show asynchronous clip updates with `callback_uri`. This is historical evidence of a callback design, not a currently supported paid voice integration or verified signing/delivery guarantee. [Node SDK examples](https://docs.resemble.ai/libraries/node), [controlling archive notice](https://docs.resemble.ai/voice-archive).

A documentation MCP endpoint is also not automatically a synthesis MCP server. The current root index points assistants to documentation lookup while the voice product pages explicitly identify their historical status. [Current documentation index](https://docs.resemble.ai/llms.txt).

## Cross-product blind spots to avoid

1. **Names hide different capabilities.** A “voice” might be an immutable reference clone, a generated speaker embedding, a paid hosted ID or a mutable library record. Do not promise portable voice identity merely because two APIs accept `voice_id`.
2. **Long input is not long-form coherence.** An API accepting a book does not establish consistent pronunciation, accent, emotion or splice quality across hours. Continuation, request stitching and infill each have different state and compatibility constraints.
3. **Streaming is not a job system.** Incremental bytes, an awaitable SDK call, WebSocket task events and restart-safe durable jobs have different lifetimes. Provider post-call webhooks are not TTS completion callbacks.
4. **Usage visibility is not admission control.** A usage endpoint, prepaid balance, subscription quota, rate limit, concurrency cap and enforced per-project budget are distinct. Only ElevenLabs' inspected sources clearly document configurable credential/group usage ceilings; this is not a negative availability claim about other providers. [Billing-group ceilings](https://elevenlabs.io/docs/overview/administration/workspaces/billing-groups).
5. **Tool installation is not production parity.** An official MCP server may expose only part of an API, use local paths, require a player, have large defaults or be archived. A documentation MCP helps find pages; it does not execute voice generation.
6. **Performance controls can alter content.** Aliases, normalization, nonverbal tags, header stripping and natural-language instructions can change what is spoken. Preserve the source and record the synthesis interpretation explicitly.
7. **Automatic repair can spend compute and replace approved work.** Evaluate bounded QA against false positives. Keep each attempt, reason and selection, and distinguish candidate creation from adoption.

## Prioritized changes to the plan

These are recommendations for the next contract/prototype stage. No changes to `PLAN.md` or implementation were made by this audit.

### P0 — must-add v1 contracts before expanding implementation

These additions strengthen the existing v1 studio contract. They do not require every backend to gain every synthesis feature: metadata, validation, correct rejection, exact-copy handling and budget enforcement are universal; phonetic control, acoustic conditioning and performance transfer remain capability-specific. An unsupported mode is visible and cannot silently fall back.

| Missing or underspecified item | Concrete addition | Scope / acceptance |
| --- | --- | --- |
| Pronunciation resources | Versioned dictionary IDs; locale; alias/phoneme kind; matching/case/priority rules; per-project/block references. Include dictionary revision in plans/cache identity. | Define capability-supported subset first. Unsupported phonemes fail before queueing. A dictionary edit marks only matching affected takes stale. |
| Spoken-text preparation | Preserve `source_text`; record normalization policy/version and rendered `spoken_text` or transform manifest, with offsets where possible. Distinguish literal text, instructions and nonverbal cues. | Test French dates, numbers, currency, names/acronyms, URLs, mixed languages and literal brackets. No header stripping or auto-polish by default. |
| Continuity-aware regeneration | Store context mode and immutable neighbor text/take references, plus engine compatibility. Expose `independent`, `preceding_text`, `preceding_audio` or supported engine-specific context explicitly. | Neighbor changes invalidate/review dependencies without automatically regenerating the whole chapter. A model without conditioning advertises that limit. |
| Performance versus identity | Separate voice revision, delivery direction and optional performance-reference artifact. Keep author text free of hidden direction tags. | Prototype typed direction fields and compatibility errors. Recording-to-performance transfer can remain unavailable until an engine supports it. |
| Acceptance and locking | Add block/take `draft`, `reviewed`, `approved` metadata and an explicit lock; define what edits invalidate approval. | A lock is a shared product-state guard, not a new blanket permission prompt. Agents can create candidates; bulk generation/adoption cannot overwrite approved selections silently. |
| Usable candidate history | A/B audition on the actual script, replay by take ID, compare resolved settings/QA, explicit select/save voice action. | Existing alternative takes need these journeys and agent operations, not just a take array. Keep preview exploration separate from committed voice identity. |
| Timing/text alignment | Reference timing sidecars to take IDs and transformed spoken-text revisions; declare word/character/phoneme granularity and confidence/source. | Never assume character timings equal editor-word indices after aliases or normalization. No mandatory base64/timestamp arrays in ordinary tool results. |
| Usage reservation | Expose estimate, reserved upper bound, consumed compute and remaining per-token/project budget; count variants, QA attempts, failed/retried work and context preparation. | Apply local resource units to self-hosted v1. Financial billing/provider integrations remain out of scope. Admission uses the enforced ceiling, not a best estimate. |
| Agent defaults and bindings | Let a named agent credential reference an allowed default voice revision/preset, language/output defaults and optional completion target. Project overrides and per-call overrides resolve in a documented order. | Return resolved settings in the plan; the same agent can speak consistently without searching for its voice on every call. Missing/incompatible bindings fail explicitly. |

Add a typed **preflight** view for bulk generation, regeneration and render: pinned revision; changed/affected/locked block IDs; reused and new work; transformation/dictionary/context identities; estimate and uncertainty; enforceable maximum work/variants/attempts; and the project or credential's remaining allowance. Preflight is metadata/planning, not speculative inference. Do not count an expensive preview as a free read.

Execution binds the preflight plan hash/revision and maximum authorized usage. Ordinary requests within the credential's existing ceiling need no extra confirmation step. A larger operation needs an explicitly raised ceiling rather than permission inferred from time passing or an optimistic estimate. Reserve allowance transactionally across concurrent jobs, release unused reservation, account actual work once, and reject admission when the bound cannot fit. If the remaining bound cannot cover the next attempt, stop before starting that work. Acceptance must cover competing reservations, retries, QA attempts, stale plans and overrun handling.

### P1 — prototype as bounded production improvements

* **Chapter/scene hierarchy and casting map.** Retain blocks, but add chapter/scene summaries and character aliases so agents can select “chapter 2, speaker Martin” without reading every line. Assisted casting/import must return a reviewable mapping and exact-text import report.
* **QA review queue.** Detect missing/extra words, clipping, silence and wrong-language signals where feasible; attach measurements and short findings to a take. Offer a bounded retry policy with a fixed ceiling and record all attempts. Human listening remains separate acoustic acceptance.
* **Preview and generation intent.** Keep “play selected existing audio” separate from “generate missing audio while playing.” Show the affected blocks and estimated/reserved work before bulk operations. Preserve headroom and gain policies already in the plan.
* **Artifact handle clarity.** Name service artifact IDs, caller-local downloaded paths and expiring remote download grants separately. Include `expires_at` where applicable; a downloadable URL is not identity or authorization for every other operation.
* **Generated integration help.** Publish a tiny versioned capability guide plus documentation index and schema-specific CLI help generated from the canonical definitions. Add optional task recipes for pronunciation correction, targeted regeneration, take approval and render.
* **Renewal/deprecation signals.** Voice references need availability/deprecation state and recovery guidance if an external/legacy source disappears. Preserve usable local references and exact provenance; do not assume a hosted library voice is indefinitely obtainable.

### P2 — later backend-specific capability experiments

Audio infill with left/right context; voice remix/localization; recording-driven performance transfer; dialogue-native synthesis; sentence/word regeneration constrained to an existing time slot; pronunciation suggestion from a manuscript; and export of richer interchange such as SSML. Each needs engine support and a measured quality/identity/timing test. Crossfade or trim alone must not be labelled model infill. Time stretching remains outside the current v1 boundary.

### Defer — no blanket studio or provider expansion

Do not add conversational telephony, a hosted multi-agent platform, video creation, automatic music generation, a public voice marketplace or a paid-provider dependency solely because a competitor has them. Imported supporting media and the current speech studio scope already cover the relevant assembly need.

## Proposed comparative evaluation additions

Keep the existing durable-job and timeline tests. Add a compact editorial/acoustic corpus: French and English names, homographs, numbers and dates, a two-speaker scene, three consecutive narration blocks and a targeted replacement of the middle block. Measure exact source retention, spoken-word omissions/additions, pronunciation adherence, voice/prosody joins, direction adherence, alignment correctness, chosen-take preservation, total attempts and compute. Use blinded human listening for subjective outcomes; separate supported-control checks from acoustic success.

Run agent tasks through the same proposed API/CLI/MCP: discover a usable voice, audition three candidates, save one, create a project dictionary, correct one name, regenerate only affected blocks, keep approved neighboring takes and render. Measure correction turns and total model-visible tokens as well as tool count. One overloaded tool that repeatedly fails selection is not efficient.

No commercial provider was exercised for this audit. A later comparison would require explicit provider/account authorization and a separately bounded corpus/usage budget. This document supports contract choices and prioritization; it does not certify model quality or recommend purchasing a service.
