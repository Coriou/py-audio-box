## Verdict and evidence boundary

**GO — source audit sufficient for a bounded build-versus-adapt comparison and contract/prototype stage.** The audit covers whole studios, serving backends, commercial production/agent workflows and browser components, and distinguishes documented features, inspected source and untested behavior. Canonical upstreams and selected commit pins make the important adoption objections reviewable. It is sufficiently thorough for this decision; it is not an exhaustive market inventory.

**No adoption or full implementation GO.** Runtime compatibility, actual agent context cost, browser accessibility/memory, acoustic quality, shipped dependencies/licenses and operational ownership remain qualification work. “Not established in inspected sources” must remain an evidence limit, not a claim that a competitor lacks the feature. Mutable vendor/component documentation must be pinned to the version chosen for a later prototype.

The prior R2 GO survives at the contract/prototype boundary. Its bespoke implementation recommendation is now provisional: the new audit provides enough whole-product overlap to require a genuine reuse comparison before large implementation. A final incorporation read of the amended `PLAN.md` and `ACCEPTANCE.md` confirms the dispositions below at the required planning depth. **No unresolved blocker remains for that bounded stage.** Independent reports' P0 labels do not automatically add release requirements; the plan resolves their broader suggestions.

## Architecture disposition

1. **Voicebox is the first whole-studio adaptation candidate.** Its voice/profile/take/timeline/MCP overlap justifies testing adaptation. Source inspection confirms in-memory coroutine dispatch and task cancellation, plus a story exporter that skips unavailable media and normalizes peaks. Durable execution/fencing, confirmed process termination and strict rendering therefore require substantive integration. These differences justify a comparison, not automatic rejection or a claim that a thin adapter suffices.
2. **Compare it with a shared service plus Waveform Playlist's minimal core/engine/view subset.** The component has meaningful overlap with editing mechanics; package/version coherence, overlap constraints, browser memory, keyboard access and service-revision mapping remain open. wavesurfer.js is a narrower audition/reference candidate. Browser undo/state must not become a second canonical project store.
3. **LocalAI is an orthogonal serving choice.** It can sit beneath either studio path if it preserves required Qwen modes, exact text/reference identity, unsupported-control errors and worker lifecycle/resource boundaries. Compare it with existing adapters; do not invent a second mutable voice registry or authoritative production queue. A service watchdog or OpenAI-compatible speech route does not establish our cancellation/publication semantics.
4. **VoiceStudio is the secondary reference/candidate.** Its persisted job metadata and event history are useful, but its own job store explicitly excludes executable-work persistence and marks interrupted jobs failed. That is different from our required durable execution policy. Its broader agent/headless features warrant retention in the matrix without building a third prototype by default.

Retain one authoritative production/voice/job domain, immutable execution inputs, revision preconditions, explicit resource isolation and strict render semantics. SQLite/control-owner topology remains the reviewed implementation baseline, subject to a documented equivalent-or-better comparison rather than silently weakening requirements to fit an upstream. Preserve current CLI/default voice behavior and legacy boundaries.

The amended acceptance scenario now uses **exactly the dependency closure** once context/dictionary dependencies exist, while retaining single-block invalidation for independent generation. Contract-stage detail must specify matching and pinning: a rule-specific matcher may minimize that closure; unsupported analysis must report conservative invalidation rather than falsely promise precision. Merely creating a new dictionary revision must not mutate a project pinned to an older revision.

Preflight must not impose an extra agent round-trip for every utterance: ordinary submission can internally derive and check the immutable plan within existing authority/ceilings. CPU/VRAM/time estimates are not guaranteed consumption bounds. Define enforceable units and interruption margins; no mandatory financial billing system or elaborate per-project credit ledger follows from this audit. Shared quotas, if offered, require transactional reservation/accounting.

## Do not turn research suggestions into scope expansion

Keep scene/chapter navigation, automated QA/retry, recording-driven performance transfer, infill, duration-constrained regeneration and transcript-driven recorded-media editing as later or capability-qualified work. Separate script, transcript and alignment provenance whenever present, without requiring a full transcript editor. Typed speaker roles and voice revisions refine existing casting, not a new assisted-casting product.

The minimal portable package belongs in v1; per-track stems, chapters, SRT/VTT, SSML, AAF/XML and native-editor handoffs need an explicit supported-format matrix and qualification. They are not all mandatory because a competitor exports them. Do not infer word timing from block timing. Review provenance belongs in the model; threaded comments, external review links and role-based approval workflows can wait.

No paid provider, hidden text-rewriting LLM, real-time duplex/telephony, global dictation, video/dubbing, music generation, DAW plugin graph or public marketplace is added. Full script/timeline production remains required in v1.

## Bounded next-stage decision

Start with a paper integration map, then at most two small fake-worker/synthetic-audio slices: Voicebox adaptation and service plus qualified component. Evaluate LocalAI through the same backend compatibility matrix. Use one shared production fixture with multiple speakers/takes, imported stereo bed, overlaps, reused/trimmed media, a changed pronunciation rule, a locked selection and missing-media failure. Include restart/late-publication faults and API → browser edit → API/export round-trip.

Record complete task/context cost, actual adapter changes, source/default preservation, required studio controls, revision/lineage compatibility, lifecycle/isolation, pinned installation dependencies, long-project behavior and upstream maintenance burden. Set an effort ceiling and select one path in a decision record. A comparison that only lists attractive features or counts existing lines of code does not pass.

No new human-only question blocks that bounded stage. Hardware/client certification and human listening/workflow acceptance remain later evidence gates. This review certifies the audit's usefulness and next-stage direction, not any product's runtime or adoption fitness.
