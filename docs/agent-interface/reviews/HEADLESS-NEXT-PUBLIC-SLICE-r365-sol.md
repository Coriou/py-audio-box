## Implementer brief: one request, one job, one new asset

**Proposed new contract, not currently callable:** `POST /v1/operations/audio_export`, CLI `audio export`, MCP `speech_audio_export`. Request: `{asset_id, rate, channels, loudness}`; `rate` is one of 24000/44100/48000/96000, channels 1/2, loudness null or finite -70..-5 LUFS. Require all four fields, no additional properties, one `Idempotency-Key`, production-write scope. Initially accept only supported managed WAV inputs; advertise that limit explicitly. No URL, server path, output filename, arbitrary filter/argv, profile/voice substitution or implicit provisioning. Optional loudness means the existing single-pass transform, not verified delivery loudness certification.

Return the existing compact durable job receipt. Reuse `job_get/list/events/wait/cancel`, `artifact_get`, `asset_get/content` and CLI verified download. The manifest must bind source asset ID/hash, requested settings, exact trusted converter identity/version, frozen input hash, output ID/hash/rate/channels/frames/subtype and ordinary attempt/owner/publication identities. The output is a separate asset; source bytes and voice version remain unchanged. No new result-download API is needed. Extend canonical schemas/validators explicitly: current job/plan operations and resolution kinds are closed, so a new operation cannot be smuggled through `speech_generate` or `project_render`.

Owner resolution verifies principal ownership and source integrity, freezes source metadata/hash and conversion settings, and admits explicit byte/frame/time/disk/output limits before submission. Same principal/operation/key and canonical request replays the same job, including after reopen; changed request conflicts. Duplicate lookup precedes volatile readiness/resolution as in existing execution submission. Missing/foreign/unsupported media returns existing stable errors; do not let a retry key capture changed source bytes.

**This is worker execution, not metadata.** FFmpeg decoding/resampling/loudnorm and writing must run in the existing supervised worker allocation, never HTTP/Dispatcher/Core owner thread or a new Redis consumer. Extract/reuse the legacy conversion behavior with a closed export descriptor and managed read-only source mapping; do not invoke its path-based CLI from the public endpoint. Resolve/pin FFmpeg availability in worker packaging; discovery never launches it. A missing converter yields unavailable/not-ready, never synthetic success. Legacy command/defaults stay compatible.

Preserve the existing Core frozen-plan/idempotency/admission/attempt Authority/ACK/reap/publication chain. Worker FFmpeg descendants must be owned and reaped before capacity release/publication; cancel acknowledgement alone is insufficient. Unknown ownership keeps the existing refusal/quarantine behavior. Conversion writes only private attempt staging; Core independently measures/hash-checks output and commits through existing publication/reconciliation. `Core._verified` currently measures PCM24 headers but then enforces synthetic or mono PCM16 speech policy (`service/core.py:595-621`): add an operation-specific export policy, do not relax those existing branches. Freeze the input hash and transform provenance, not a fake generated-voice identity. No generic command bus, second scheduler, DB-owning worker or alternate artifact store.
