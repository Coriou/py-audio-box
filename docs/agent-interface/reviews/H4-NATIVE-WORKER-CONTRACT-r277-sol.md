## One selected topology and narrow product scope

Implement **`native-qwen-v1`: a native TCP listener with TLS 1.3 and mutually pinned certificates**, contacted by the existing Docker control process through a new private runtime adapter. This is one local bridge, one native supervisor, one active attempt and one exec inference child. No remote fleet, tunnel, broker, scheduler, agent registration service or alternate transport.

The native launcher requires an explicit numeric host bind address and port. No wildcard/default external exposure; `127.0.0.1` is accepted only for a proven host-network topology, never assumed reachable from Docker Desktop/OrbStack. The packaged Docker client uses the configured host gateway endpoint (for example operator-configured `host.docker.internal`) and exact server-certificate SHA256 pin. The native server requires the exact enrolled client certificate, not merely any certificate signed by a shared CA. Configure the reachable host interface and host firewall restriction to the Docker bridge explicitly. Reachability/interface behavior remains an actual packaging gate. No VM UDS, shared `/ipc`, host pathname or SCM_RIGHTS crossing is assumed.

TLS provides confidentiality, integrity and peer authentication on every frame; the existing HMAC-only UDS handshake is not transplanted onto TCP. Require TLS 1.3, no plaintext fallback, no redirects, no TLS early data, no credential in argv/URL/public request/log. Enrollment supplies private server/client key files (0600, no-follow, fixed owner), pinned peer certificates and deployment/configuration identities. Private credentials reside only in native supervisor and Docker control; inference gets neither keys nor listener FD. Certificate rotation requires a stopped, reconciled deployment; no live trust widening. A private host listener is an explicit exposure, not a networkless worker claim.

Isolation premise: dedicated native service account/private directories, trusted immutable packaged Python/dependencies/model configuration, and no hostile same-UID writers. This is not a Linux PID namespace, seccomp/cgroup boundary or hostile-code sandbox. Darwin process limits and MPS unified-memory accounting do not establish GPU memory enforcement. If this trusted-runtime premise cannot hold, refuse the profile rather than relabel its receipt as Linux containment.

Initial profile: `qwen-mps`, public identity `device='metal'`, private descriptor `device='mps'`, topology `packaged_native`, exact `float32/sdpa`, fallback forbid, one variant, reuse never. Float32 is a deliberate initial contract choice, not a compatibility/performance finding. Bundle capabilities must explicitly allow this tuple; actual failure leaves unavailable, with no automatic float16/CPU substitution. Only `speech_generate` for existing owned immutable `qwen_preset` or `qwen_clone` versions. No VoiceDesign, prepare, public prompt import, automatic model discovery or universal multivoice installer. The first hardware gate may qualify preset generation alone; clone must remain separately unavailable until its reference/cancel lifetime is qualified.

CPU baseline stays on existing Docker Kokoro/Pocket policies. Intel Mac native CPU may later use this same finite bridge with a separately reviewed CPU profile/topology contract; it is not enabled in this lot. CUDA installed integration and all other r270 release obligations remain separate mandatory work.

## Private native protocol: closed shapes and caps

Use version `native-qwen-v1`, 4-byte network-order length plus canonical UTF-8 JSON; frame ceiling 65536 bytes, duplicate keys/nonfinite values/unknown fields/unknown operations refused. Authority's existing serialized snapshot ceiling remains 48000 bytes before allocation. TLS handshake and each command complete within 2 seconds; active-attempt operations additionally use the remaining original cutoff. Stop/observe/collect/ack remain usable after that cutoff with a fresh 2-second communication bound. At most four authenticated connections (three lifecycle slots, one transfer slot), queue depth eight, one active allocation, no unbounded wait/stream response. Watchdog is independent of TLS handlers, hashing and journal I/O.

Every request has exactly `{version, deployment_id, configuration_sha256, lane, boot, request_id, runtime_id, binding, op, body}`. IDs use existing bounded job/attempt IDs; deployment/lane/boot/request_id are lowercase 32-hex, digests 64-hex. `runtime_id` is null only on hello/prepare; binding is null only on hello. Initial hello uses null lane/boot; response supplies them. All other operations require exact known lane and current boot, except historical observe/collect/ack which must name the allocation's original boot. TLS peer must match the configured deployment on every connection. Responses echo request_id/op and exact allocation tuple, with `{ok,value}` or `{ok,error}` as exclusive closed variants. Error is one finite reason code, never backend traceback/path/text.

`hello` body `{}` returns `{deployment_id,configuration_sha256,lane,boot,quarantined,launches,runtime_manifest_sha256,inventory}`. Only this enrolled server may supply inventory; profile readiness is not inferred from hello. `prepare` body `{snapshot}` recomputes Authority binding from the four-element snapshot and independently validates all relations, profile/registration and allowed asset IDs. It returns one runtime_id `lane/boot/<32hex>` and state. Bind before start through current DispatchStore. Same snapshot/binding returns same allocation, including after lost ACK. Changed binding for the same job/attempt/generation/owner/staging tuple refuses. Retain at most 64 lifetime records and 8 unacked; exhaustion refuses, never evicts unresolved history. No automatic rotation or new campaign machinery.

Remaining operations and exact bodies:

- `put_input`: `{sha256,bytes,offset,data}`. `data` is canonical base64 of 1..32768 decoded bytes; total is exactly the descriptor reference_bytes, at most 24000000. Only the clone reference digest authorized by this allocation is accepted. Preset has zero input blobs. Offset must be current exact offset; an identical replay of an already accepted chunk is accepted only after comparing stored bytes. Gaps, overlaps with changed bytes, wrong lengths and post-completion writes refuse. No caller filename or cache lookup by digest alone.
- `start`: `{}`. Requires all input bytes complete/hash/PCM authenticated and current native registration, bundle and inventory valid. Sets durable launch intent before Popen. Repeated start never spawns again, including after timeout/boot change. Model bundles are pre-provisioned, not uploaded through this bridge.
- `observe`: `{}` returns exact runtime_id and `alive|stopped-and-reaped|unknown`. Live means exact supervisor-held handle, not TCP reachability. Prepared allocations are still owned until stopped or started.
- `stop`: `{}` idempotently requests supervisor fixed TERM/KILL escalation. No signal/PID/process-group argument is accepted. A stop ACK is not death proof.
- `collect`: `{}` returns `{receipt,proposal,output}` with nulls until terminal. Proposal is the existing exact worker `{message,manifest}` (1.3.0); output is null or `{sha256,bytes}`. Exactly one generated WAV, capped at min(descriptor.max_output_bytes,1048576), no archive, filename or URL. Proposal may be exposed only after native receiver closure, verified child result and owned exit; it conveys no publication authority.
- `get_output`: `{sha256,offset,bytes}` where bytes is 1..32768 and offset is bounded within the terminal allocation's sole output. Response `{sha256,offset,data}`. Repeated reads are idempotent. No arbitrary blob read or cross-allocation deduplication authority.
- `ack`: `{}` only after terminal. Control sends it only after durable Core outcome and reservation transition. Retains tombstone/receipt; may discard only this record's fixed transfer files after exact ownership checks. A cleanup failure quarantines storage; no recursive sweep. ACK replay returns the same success.

All body validators reject bool-as-int, extra keys and nested oversized strings before I/O/allocation. Partial input is never loadable; final full size/hash and complete mono PCM16 format are checked independently by native supervisor and child. Store as `<private-root>/<allocation-token>/input-<sha256>` using supervisor-derived paths, O_EXCL/no-follow, 0700 directories/0600 files, no hardlinks or symlink components; no public filesystem authority. File writes flush/fsync before marking complete. Each allocation reserves input+output+temporary-copy worst case, and all transfer files across retained records have a 64 MiB aggregate ceiling; admission refuses before exceeding it. Cap journal metadata at 1 MiB. Free-space floor remains at least the existing actual-work gate plus declared attempt disk demand; qualification must measure adequate model/runtime headroom separately.

No model weights in transfer, no pickle, no import/module selector, no arbitrary public method or callable. A disconnect never grants restart/retry authority. Transfer uses bounded chunks to avoid whole-reference JSON frames; all chunks consume the same attempt deadline, not a refreshed budget.

Install a native-service-only fail-closed spawn guard before upstream imports: reject Python subprocess, multiprocessing start, fork/forkpty/posix_spawn/system/exec APIs after the child entry has begun; set tokenizer parallelism off and loader worker count zero wherever supported. Use the existing parent-side encoded execution/result framing over the inherited socket, with spawn-token/Authority binding in its private config; Linux SO_PEERCRED is not required or fabricated. Supervisor receiver validates complete output hash/size/PCM and oracle relations, closes the socket and all received/inherited parent descriptors, then records receiver_done. Unexpected EOF/result/exit code means failure, even if some bytes arrived. Supervisor watchdog requests TERM at cutoff/cancel/shutdown; after 0.2 seconds requests KILL while exact identity remains live. Exact handle wait has a 1-second bound; unknown wait, identity mismatch or unconfirmed receiver shutdown retains handle/allocation and quarantines. Direct child exit code zero plus receiver_done plus the no-extra-process bundled-runtime premise proves the one allowed model process exited. It does not prove death of arbitrary descendants. Never use `os.kill(-1)`, Linux ECHILD, group disappearance, pid existence tests or native UID alone as native terminal authority. Receiver must finish and all owned handles must have exact waits before STOPPED; there are no allowed helper processes in this mode.

Native journal uses version `native-journal-v1`, deployment/config digest/lane, bounded allocation records, original allocation boot, phase `prepared|launch-intent|terminal`, ACK, input completion and optional terminal receipt/proposal/output digest. Checksummed atomic write/fsync/replace/directory-sync and exclusive flock precede replies. Persist launch-intent before Popen; persist terminal before reporting STOPPED. A failed durable write is UNKNOWN/quarantine even after an actual wait. It is a receipt journal, not another job database.

Receiver_closed is true; reaped true only after the conditions above. No native engine_uid. `timely` requires valid proposal, zero exit, output complete, receiver closed and exact wait before original cutoff. Failed/cancelled attempts can have reaped true and timely false. Validators bind the full receipt to the immutable Authority and trusted deployment; a valid-looking JSON receipt is not independent OS proof.

After child reap, retain current conservative clone conditioning rule: only literal empty owned 0700 directory removal; no recursive cleanup or adoption of a nonempty snapshot. Interrupted nonempty conditioning blocks terminal receipt and restart, retaining UNKNOWN. A later concrete I/O change may avoid named snapshots if actual upstream accepts safe bytes/FD input, but do not assume that now. Preset has no conditioning namespace.

Graceful supervisor exit stops/reaps the current handle before exit. Supervisor crash/host reboot loses wait ownership: restarted supervisor never reacquires authority by PID/PGID, start timestamp, ECHILD or assuming reboot killed everything. Any prepared/launch-intent record without durable terminal receipt is UNKNOWN; no automatic relaunch, replay, capacity release or replacement. Control retains reservation and blocks lane.
