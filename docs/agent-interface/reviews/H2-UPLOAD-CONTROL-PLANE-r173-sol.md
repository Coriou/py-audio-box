## Public upload and owner boundary

Borrowed-owner `create_voice_app` now implements authenticated `POST /v1/assets` with raw `audio/wav` bytes, not JSON/base64. It accepts no path, filename, caller principal, provenance or idempotency key. Query extras refuse. `StaticCredentials.resolve(..., required_scope='production-write')` requires **both read and production-write**. Its default remains read. Read-only tokens cannot upload; explicit configuration/revocation remains operator owned. Custom resolvers used for uploads must implement the required_scope keyword and equivalent policy. No default credential was introduced.

Transport validates content type, a single syntactically valid optional Content-Length, declared maximum, actual counter, actual-versus-declared equality, nonempty completed EOF and a whole-body deadline (default 15 seconds; explicitly injectable positive maximum 60 seconds). Chunked input without Content-Length is supported. Buffer budget is 25,165,824 bytes. Accepted individual ASGI chunks are at most 65,536 bytes; larger chunks refuse resource_limit. Exactly one upload is admitted per app instance, using a nonblocking semaphore before buffering, held through owner completion. This bounds service-owned upload buffering to one 24 MiB BytesIO plus finite allocator/immutable-value/receive-chunk overhead; it is not a measured RSS bound and cannot bound allocations already performed by an upstream ASGI server. Deploy one factory instance for the owner. Actual installed server chunking is not qualified here: a server delivering chunks above 64 KiB will encounter the explicit refusal even if the total WAV would fit. No listener/network test or load benchmark is claimed.

Incomplete, disconnected, timed-out, over-limit and forged-length bodies never call the owner. Completed immutable bytes alone pass through explicit `Dispatcher.call('asset_ingest', trusted_principal, bytes)`; call admission rejects streams/nonbytes and oversized byte values before deepcopy/queueing. The owner branch calls existing ingest_local on its own thread. No network stream runs on the DB owner. Media validation remains H1-owned: complete but invalid RIFF reaches ingest, which refuses and cleans its own temporary files; transport validity is distinct from media validity. Existing PCM16/24/32, mono/stereo, 8–48 kHz, 60-second and RIFF policies are unchanged.

Success returns the existing compact typed asset metadata: opaque asset ID, hash, media measurements/format, provenance and authenticated principal. Metadata output is capped at 2048 UTF-8 bytes. It creates an asset only; no clone, saved voice, voice version or engine readiness is implied. New upload declaration replaces the previously unavailable planned JSON/idempotent receipt declaration with the actual binary/non-idempotent operation. No automatic upload retry or success synthesis exists.

Queue/storage/timeout errors return sanitized not_ready without an asset receipt. A timeout can leave queued/running work whose eventual outcome is unknown: the owner Future is not cancelled and may later commit an asset. Upload admission remains closed for that app instance after not_ready or cancellation/unknown owner outcome, preventing successive retained 24 MiB buffers. This deliberately conservative behavior also closes admission on definite queue-full/storage failures; reinitializing the app is operator lifecycle work, not an automatic retry. No promise of rollback after a dispatched request or idempotent recovery is made. Retained memory/work can last until the owner consumes the command; owner death/lifecycle qualification remains separate.

## Authorized asset reads and compact catalogue

Production implements existing `asset_get` and `asset_content` declarations with no fixture fallback. A fixed domain owner function checks direct principal ownership in trusted asset metadata before Core.asset verification. Historical assets without direct principal_id are unavailable through this slice; no compatibility scan or fixture adoption is exposed. Foreign/missing IDs return not_found, including foreign assets whose bytes are tampered.

Content uses the existing explicit range/base64 response contract, capped here at 64 KiB decoded per HTTP range. Core first verifies metadata/file; the domain then opens the managed asset through a no-follow directory and leaf descriptor, verifies regular/current-user/single-link/24 MiB bounds, hashes the full file with bounded reads, reads the requested range from that same descriptor, and checks stable inode/size/mtime/ctime before closing. Only detached bounded data reaches HTTP; no descriptor spans client/network lifetime. This intentionally hashes the file again for every range, so it is bounded work per request but not optimized large-file throughput. CLI download retains complete SHA256 verification and exclusive local publication. MCP inline content retains its 3072-decoded-byte explicit opt-in limit.

`voices_list` preserves its existing ID-list/cursor response and now calls explicit `voice_summaries` -> Core.voices.summaries. New `voice_versions_list` (`GET /v1/voices/{voice_id}/versions`, CLI `voice versions ID`, MCP `speech_voice_versions_list`) calls explicit `voice_version_summaries` -> version_summaries and returns compact version IDs with numeric pagination. Neither calls full get. Existing voice_get/version_get shapes and full history are preserved, with resource_limit for oversized full output. All voice responses remain capped at 2048 UTF-8 bytes; max-length IDs can require a smaller requested page, and oversized pages refuse rather than truncate. This is an output bound, not constant-time indexed DB work or a bound on every historical full-read allocation.

Discovery advertises only actual new operations, no models/profiles/downloads. Operation detail marks upload as implemented rather than implemented_read. Existing/new asset and version-list error declarations include actual sanitized emitted codes; invalid_audio maps to existing invalid_media, foreign_media to missing_media. Domain ContractError is a ValueError: owner not_found/resource/media errors must reach domain translation instead of being indiscriminately treated as schema errors. No native exception/path/payload is echoed.

## Client host filesystem permission

CLI: `python -m clients.cli asset upload /absolute/client/file.wav`, using explicit credential or SPEECH_CREDENTIAL. HTTP.upload_file streams at most 64 KiB at a time, checks regular file/size, stable size/mtime/ctime, exact finite read and EOF; paths never reach the server. Every path component and leaf uses no-follow descriptors, with nonblocking leaf open so FIFOs cannot hang. Symlinked system path prefixes therefore require an explicit canonical client path (for example /private/tmp rather than /tmp on macOS).

MCP: `speech_asset_upload_file` is advertised only when the operator explicitly configures absolute `SPEECH_UPLOAD_ROOT`. Its schema accepts one relative client-host path, no inline bytes. This configuration grants the MCP process host filesystem read permission within that root. Absolute inputs, parent traversal and symlink components/leaves refuse; no-follow root traversal avoids resolve/check/open races. Disabled configuration returns forbidden. CLI may explicitly choose any readable local file; MCP must use its configured root. Tool and operation metadata document that this is a client-local permission boundary, not a server path capability. HTTP/CLI/MCP preserve typed asset/error parity; generated opaque upload IDs intentionally differ per invocation.
