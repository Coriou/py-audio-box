## Architectural and release risks

Native history accepts fewer than 64 jobs, all succeeded, single-attempt and non-clone, under the same immutable boot/trust (`native_activation.py:149–174`). Supervisor journal/registration allocations are separately capped without renewal. Ordinary cancellation, failure, clone use, exhaustion or a changed supervisor boot can prevent subsequent owner activation. These refusals are appropriate safety behavior, but they block a general durable-service release. Raising caps or deleting history is not a remedy. Clean control restart is not host-reboot recovery.

Preset version derivation hashes the whole enrolled template, including native identity. Renewal therefore needs an explicit policy for already saved versions and historical jobs; simply generating new enrollment inputs risks making existing voices unusable. Keep immutable voice provenance and historical Authority intact, and reauthorize execution explicitly. This is a design obligation inferred from `owned_preset_context`, not an observed runtime failure.

The native launcher binds control loopback and does not establish Docker host reachability, credential mounts or firewall isolation. No reviewed arm64 wheelhouse/ABI exists. These and supported stopped/reconciled renewal are release prerequisites, but should be completed as one installed lifecycle deliverable, not further disconnected package microreviews. NATIVE-PACKAGE.md also retains superseded first-start/no-launch/no-onboarding statements before later amendments; consolidate its current operator instructions with that deliverable.

Constrained CPU remains first-class, not the definition of the entire product. Rootful Linux-only enrollment does not fulfill the constrained Intel Mac install promise; disabling host guards does not fix it. Current 25-second production dispatch caps and native 30-second bounds require measured cold/warm feasibility. Do not globally relax them or impose a permanent CPU-sized concurrency limit on stronger hardware. Preserve explicit engine/model/voice identity: Kokoro/Pocket are explicit alternatives, never silent substitutes for a Qwen voice.
