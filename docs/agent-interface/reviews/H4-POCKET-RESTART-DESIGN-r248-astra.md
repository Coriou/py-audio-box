## What actually causes the blockage

`worker/runtime_child.py:run_generation` exclusively creates `conditioning` under the allocated stage, mode0700, owned by the child. Three named temporary-file lifetimes matter: the wrapper reference WAV in `worker/engines/pocket.py:execute`, the translated YAML in `PocketBackend.__init__`, and the backend reference WAV in `PocketBackend.synthesise`. Normal unwinding unlinks these files; neither wrapper nor backend removes the directory. SIGKILL cannot run that unwinding.

`Reconciliation._collect` deliberately treats the remaining name as `unknown_foreign/unknown_namespace`. Its persisted diagnostic is sticky: later disappearance does not clear prior UNKNOWN or unresolved integrity. Consequently a repair must finish **before the first healthy startup inventory**, not delete a name after reconciliation has latched it. A Core-only reopen is not the requested Dispatcher restart test.

The r244 `committed_referenced` workaround was semantically wrong: `_installed_detached_source` reserves that classification for regular managed assets with exact metadata/hash/coverage. R246 correctly removed it. The existing `owned_synthetic_transient/attempt_record` category can represent attempt directories, but its live and detached readers use closed path rules. Adding `conditioning` to both allowlists would still conceal nonempty private descendants; current stat fields cannot prove an empty child set. Do not do that.

## Three options and decision

1. **Post-reap empty-directory removal — selected for the next bounded source lot.** Preserve the backend contract and current snapshot unwinding. After exact tree reap, let a narrowly credentialed helper attempt a single descriptor-relative `rmdir`. The kernel atomically rejects nonempty directories; no durable emptiness statement or inventory-reader extension is needed. This is the smallest correct repair of the demonstrated permanent empty-directory failure. Nonempty forced-cancel leftovers remain blocked.
2. **Eliminate persistent snapshots — preferable only if arbitrary interruption must immediately become restart-clean.** Simply moving the same named files into `/tmp` relocates retained bytes and inode consumption; container tmpfs is not an attempt-private lifetime and does not disappear when a child is reaped. `TemporaryDirectory` likewise depends on cleanup that SIGKILL skips. Anonymous/FD-backed snapshots or a byte/tensor conditioning entry point could remove the problem, but all three temporary-file sites must change together. Current code explicitly validates `.wav` paths, reopens names and passes a YAML filename upstream. An unlinked file or `/proc/self/fd/N` is not a demonstrated drop-in replacement; suffix handling, reopening, upstream lifetime and native portability need a concrete adapter contract. No network/upstream/model inspection was authorized here, so compatibility is unproven. Do not sell a speculative FD substitution as the smaller implemented fix, or fall back silently to retained named files.
3. **Retained empty-directory attestation — do not commission now.** R247's proposal can be made sound, but requires cross-UID observation, durable identity/emptiness binding, paired journal/inventory/history consumers and mutation tests. It still cannot call nonempty crash leftovers clean. It buys no useful voice feature over removing an empty directory after proven death, and broadens durable compatibility obligations unnecessarily.

The scope distinction is explicit: if the parent's required exit means *every cancellation phase*, option 1 alone does not satisfy it. Then the next product step is option 2's concrete snapshot-I/O change, not a larger evidence framework or pretending an empty-only test covers cancellation during model loading/conditioning. For the immediate empty-directory blocker, implement option 1 now.

## Concrete Sol implementation contract

### Supervisor lifecycle and one narrow helper

Own `worker/runtime_supervisor.py`, a small dedicated helper such as `worker/runtime_conditioning.py`, and focused supervisor/Pocket tests. Keep cleanup out of Core, reconciliation, recovery and the child. `runtime_child.py` needs at most a comment/contract update: it must continue to create exclusively and must not remove the directory in a `finally` while descendants may live.

In `RuntimeSupervisor.tick`, use the existing `waitpid(-1, WNOHANG)` loop's **ECHILD** condition, receiver completion and exact active allocation. A leader exit, stop request, timeout, ESRCH, proposal or a caller-provided `reaped=True` is insufficient. Freeze the existing engine reap timing/count before launching the housekeeping helper. Keep the lane occupied, prevent another prepare/start, and coordinate the watchdog under the existing tree lock so its old stop escalation cannot kill housekeeping or target a later allocation. Do not hold that lock across a blocking subprocess wait.

For the Pocket execution mode only, invoke bounded housekeeping before `change(... phase='terminal', receipt=..., proposal=...)`. Use the journal allocation's validated context, job/attempt/staging identity and allocated child UID, never a public path or directory glob. No generic cleanup RPC or operator CLI is needed. The helper is synchronous, has no descendants, is waited by its exact process handle, and has a finite timeout; on timeout explicitly kill/wait that helper, and retain quarantine if helper death cannot be confirmed. Preserve the existing engine receipt's meaning and deadline, rather than counting helper activity as engine work or recomputing a fresh execution budget.

The helper must:

- Walk fixed `/staging` and the exact single-component staging name with directory FDs and `O_NOFOLLOW`; validate root policy and the attempt directory's expected owner **10001**, group **allocated child UID**, mode **0770**, device and stable name/FD identity. On this Linux runtime use `O_PATH|O_DIRECTORY|O_NOFOLLOW` for the mode1733 staging root: UID10001 has search permission there, not directory-read permission. Open the owned attempt directory readably for fsync. No `resolve()` that hides symlinks, recursive traversal or sibling search.
- Inspect only literal `conditioning` with no-follow stat relative to that FD. If present, require a real directory on the stage device, child UID/GID ownership and mode0700. Reject symlink, ordinary file, foreign owner, unexpected mode or changed identity. Do not infer emptiness from size, link count or timestamps.
- Call exactly `os.rmdir('conditioning', dir_fd=stage_fd)`. Successful `rmdir` is the kernel's emptiness check; no read permission on the private directory or descendant enumeration is needed. ENOTEMPTY/EEXIST means retained nonempty UNKNOWN, never recursive deletion. Other errors or identity changes also fail closed. Absence is acceptable for an otherwise verified attempt stage, including cancellation before creation; a stage never created on a stopped prepared allocation needs its own explicit no-start branch, not a broad ENOENT catch.
- Fsync the modified stage directory and revalidate its bound identity before reporting success. Never remove the stage itself, output.wav, a snapshot file, or any other entry. The service's trusted control owner and dead exclusive child are the writer-exclusion premise; do not claim resistance to a concurrent malicious privileged host/control writer.

Only successful completion/verified absence allows the normal terminal journal save. Preserve the original binding, runtime ID, engine UID, original deadline, timely flag and reap method. Existing `Journal.save` durability followed by Dispatcher collect → validated terminal result → resource release → ACK is sufficient. **Do not add `cleanup_ok`, an emptiness receipt, new journal phase, inventory reason or schema.** The receipt continues to attest reap; cleanup ordering is an implementation invariant, not a new interpretation of all historical terminal receipts.

On nonempty/refusal/helper/fsync failure, do not produce a successful terminal transition or release/ACK from that path. Retain the existing nonterminal record, mark the current lane failed/quarantined, and clear/retire the active handle only after owned processes are accounted for. This intentionally preserves UNKNOWN even if physical engine death occurred. Do not let the next tick accidentally terminalize after a failed cleanup. Make error classification testable internally without a new persistent diagnostic subsystem.

### Cross-UID permissions: no extra capability

The installed worker has SETUID, SETGID and KILL, **not DAC_OVERRIDE**. UID0 cannot be assumed able to traverse the control-owned stage or inspect a child-owned mode0700 directory. Launch the narrow helper as **UID10001, GID=allocated child UID, supplementary groups=[]**, using the existing supervisor credential-switch pattern. UID10001 owns the stage and can remove an empty directory entry within it regardless of the entry's child UID. It does not need to open or chmod that directory. The fixed `/staging` root allows traversal; the control service's read-only mount does not restrict the worker's separate writable staging mount.

No host-root agent, new capabilities, ACL/chown repair, Docker socket or control-side writable mount. Prove exact subprocess credentials and FD operations in source tests; actual kernel permission behavior under the packaged caps/mounts is later actual evidence, not something same-UID fixtures establish.

### Readers, crashes and old state

**No production changes expected in** `worker/runtime_journal.py`, `service/reconciliation.py`, `service/recovery.py`, `service/install_policy.py`, `service/dispatch_store.py`, `service/core.py` or Dispatcher terminal/release ordering. Reconciliation still classifies any retained conditioning name UNKNOWN. Clean success leaves only already-supported stage/output/asset objects. Exercise the real readers to verify that premise; do not expand their acceptance to make a fixture pass.

Crash before cleanup, during it, or after rmdir/fsync but before durable terminal journal save leaves a prepared/started record: existing startup quarantine, no inferred death and no automatic retry cleanup. A crash after terminal save uses the ordinary receipt/Dispatcher reconciliation path; no directory is expected. Old terminal records are **not** retroactively proof that cleanup happened. Old conditioning directories, previously latched UNKNOWN and historical evidence roots stay untouched and blocked under existing rules. No boot-time sweep, replay of removal from an old receipt, integrity reset or migration is part of this lot.

Control restart while an attempt is still live can observe the namespace and latch UNKNOWN under the present startup ordering. This fix does not promise transparent mid-flight service restart. It establishes clean restart after completed supervisor finalization; interruption/uncertainty remains conservative.
