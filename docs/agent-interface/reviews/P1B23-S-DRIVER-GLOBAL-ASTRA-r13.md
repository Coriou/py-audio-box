## Concrete findings and one repair batch

### F1 — blocking, actual: unsupported open API at both private-write seams

Driver:55 and :84 pass `opener` to `Path.open`. The first fails deterministically before checkout; correcting only publish would merely move failure to capture opening. r12 source review incorrectly asserted that this API accepted/passed through the opener. AST parsing/compilation cannot establish keyword compatibility.

Use built-in `open(path, 'x', opener=...)` and `open(path, 'xb', opener=...)`, retaining the explicit `os.open(path, flags, 0o600)` creator and all supplied exclusive flags. Built-in open accepts path-like objects. An explicit os.open/fdopen implementation is also valid but requires careful fd ownership on fdopen failure; it is not necessary for this correction. Do not remove explicit0600, rely on022, or chmod after creation. Keep the private0700 parent and scoped022 checkout/restored077 behavior. Exclusive O_CREAT|O_EXCL rejects an existing leaf, including a symlink; adding O_NOFOLLOW is compatible but does not replace checked parent components.

Official signatures: [Path.open](https://docs.python.org/3.14/library/pathlib.html#pathlib.Path.open), [built-in open](https://docs.python.org/3.14/library/functions.html#open). The live 3.14 docs display a later patch-version heading; the relevant signature distinction agrees with the exact retained 3.14.7 TypeError. No inference that a later patch was executed.

### F2 — blocking failure-path closure: leader exit is not process-group completion

Driver:85 creates a new session. At :106–108 it sends SIGKILL to that process group **only if proc.poll() is None**. Concrete source counterexample: a command leader exits, a descendant in the same group retains a capture pipe, selector waits to the deadline, timed becomes true, poll reports the already-exited leader, killpg is skipped, wait returns the leader status, and the descendant remains alive. Recipe's internal Git and command plugins/hooks make child processes a real wrapper concern, even though no such event occurred in r12. The same omission applies to overflow/capture failure after leader exit.

For timeout/overflow/capture failure after a successful spawn, attempt one kill of the owned session/process group independently of leader liveness, tolerating ProcessLookupError, then retain the bounded leader reap and explicit unresolved status. Do not claim this reaps grandchildren, kills escaped sessions, completes a Docker daemon operation, or solves PID-reuse/uninterruptible-I/O races. No native fork/crash campaign is needed: a subprocess fake with exited leader and still-open pipes exercises the exact branch. Preserve remote Docker uncertainty and prohibit destructive cleanup/lane release on that uncertainty. [Popen session and wait semantics](https://docs.python.org/3.14/library/subprocess.html#subprocess.Popen), [os.killpg](https://docs.python.org/3.14/library/os.html#os.killpg).
