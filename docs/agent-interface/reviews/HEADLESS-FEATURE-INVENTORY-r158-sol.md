## Registry safety and meaningful existing coverage

Reuse the repaired registry behavior already in root: per-registry process lock, fsynced temporary JSON, staged clone finalization/rollback, prompt reference hashes and checkpoint/revision matching, safe portable archives. Do not import arbitrary `.pkl` from users or treat a legacy local cache as trusted merely because it has a sidecar. Explicit references and authorization/provenance must survive clone → voice version → speech → export.

Limits still matter: JSON replacement is not a fully durable multi-file transaction; direct source/ref/prompt copies exist, directory fsync/restart recovery is not comprehensively supplied by this registry, unlocked readers can observe replacement gaps, and registry paths are not a service ACL/no-follow sandbox. Rename/delete are destructive mutable operations. Service should publish immutable voice versions via staged files plus durable metadata, archive identities instead of breaking existing jobs, and preserve existing versions on import/clone failure. Bound decoded duration/bytes/entries, validate audio rather than extensions alone, protect against symlink races and disk exhaustion, and never trust client filesystem paths or URLs as worker paths.

## Minimum end-to-end acceptance and release boundary

Follow exact request/receipt schemas rather than assuming voice_prepare itself creates a named voice. Map the same journey to canonical `voice prepare/save`, `speech generate`, `job get`, `project assemble/render` CLI names and `speech_*` tools from the catalogue; these are future commands/tools, not currently callable examples.
