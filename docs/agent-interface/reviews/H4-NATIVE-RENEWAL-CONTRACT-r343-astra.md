Configuration digest and lane may change as explicit successor identity, but only after a closed semantic comparison of old/new private inputs. ## 3. Stopped transaction and interruption recovery

Expose a finite private maintenance API/explicit operator CLI with three steps: `begin`, host `retire`, control `commit`. These are proposed commands, not existing commands to run now. No HTTP/CLI/MCP public provisioning operation is added. Public execution clients remain unchanged.

1. **Begin under exclusion.** Public owner has drained/closed successfully. Obtain the same process/thread registry and `control.lock` ownership used by Core; use a narrow maintenance form of the existing ownership primitive, with read-only SQL and no Core recovery/schema initialization/scheduler. Do not acquire an unrelated lock or construct a second Core. Validate predecessor enrollment and raw Core membership/terminal constraints. Persist an intent before asking the host to retire. Bind request ID, predecessor, complete stopped Core evidence fingerprint and expected immutable compatibility inputs. All startup paths now refuse normal admission while this intent is incomplete. Release maintenance ownership between explicit steps; reacquire it and revalidate on every continuation.
2. **Retire old host.** Operator stops old supervisor, then the host helper takes `native.lock`, performs the full validation above, and publishes retirement/export. A live supervisor, active/unreaped child, launch-intent, unACKed record, temporary journal or uncertain close refuses. Do not kill, repair, ACK, infer reap from PID absence, or clean evidence as part of renewal. The old server need not be restarted to obtain a receipt.
3. **Prepare successor privately.** Provision a new host journal root and explicit new trust/config/origin mapping; retain old roots. New supervisor starts with no allocations, uses the unchanged package/model bytes, and checks the exact predecessor retirement/export and remaining capacity. Old credentials need not work. Supply the new boot/lane explicitly to new control enrollment and templates; pinned hello must equal every supplied field, show no quarantine and zero current-epoch launches. A second unexpected boot before commit refuses; do not learn it or silently retarget the pending request.
4. **Commit under exclusion.** Re-read predecessor Core evidence, retirement export and origin templates, run offline full history validation, validate current inventory/profile/compatibility and new TLS hello, repeat immutable input reads, then publish the one successor commit document. Dependencies must already be durable. This final file is the sole activation commit point; no SQLite mutation is coupled to it. Preserve old Authority, jobs, catalogue, artifacts, reservations and transport files byte-for-byte.
5. **Reopen normally.** Resolve only the unique committed chain tip. Recheck offline old epochs and live current epoch before schema recovery/scheduling. Current hello launch count equals only current-epoch dispatches; old jobs are still fully validated and counted for cumulative limits. Existing Core reconciliation/publication/import fences remain in force. Admission starts only after all proofs and the final bracket succeed.

Publish each document using a deterministic transaction-owned staging name, exclusive creation, full write/fsync, atomic rename into a previously absent final name and parent fsync. Never overwrite an unexpected final/staging file. The request ID and canonical input fingerprint are the idempotency key: repeated exact requests return the same committed result or resume the next missing step. Changed inputs with the same ID refuse. Different IDs cannot fork a pending or committed predecessor.

Crash cases are deliberately finite:

- Intent durable, no retirement: normal startup stays blocked; same request can resume host retirement. No automatic rollback to old admission.
- Retirement/export durable, control seal absent: old host remains retired; resume by validating the same retained export and unchanged Core evidence offline. Old TLS availability is not required.
- All inputs durable, commit absent: validate again and publish the same commit. Never infer commit merely because the new supervisor is healthy.
- Commit rename visible but fsync acknowledgement lost: explicit same-request resume validates all bytes and re-fsyncs the exact owned final file and parent before reporting committed. Normal startup may conservatively require that explicit resume after detectable partial staging; it never repairs one itself.
- Truncated, foreign, symlinked, conflicting or unrecognized staging/final evidence: retain and refuse `native_renewal_partial_or_conflicting`. Do not delete/truncate it or fabricate a successful phase. Well-formed completed phases resume idempotently; arbitrary partial bytes do not.
- Candidate supervisor changes boot or dies after commit: do not rewrite the commit. A further explicit renewal is required, including a clean retirement of that candidate epoch (empty history is allowed). This spends an epoch slot; it is not automatic restart recovery.

Old supervisor unavailability alone is therefore not a history failure **when a valid trusted retirement export exists**, or when its intact stopped journal can still be exported locally under the lock. If both that proof and accessible intact journal custody are absent, refuse `native_history_evidence_unavailable`; local Core receipt text alone is insufficient. Never turn unknown ownership into a retired epoch. The first slice does not recover a lost host disk, roll back the whole installation, or prove absence of hostile same-UID rollback.

## 6. Capacity decision: retain and refuse, never reset accounting

This slice renews trust/freshness, **not retention capacity**. A fresh host journal is an execution-identity boundary, not fresh capacity. Carry retired usage in the committed predecessor chain to both control admission and supervisor allocation checks. Deduplicate origin templates by canonical principal/origin identity; carry the count of all retained allocation registrations, all journal records and existing worst-case byte charges. Do not count a repeated identical origin twice, and do not omit retired allocations because their in-memory registration cache disappeared.

Keep the existing 64 ceilings and stricter fewer-than-64 history requirement. Conservatively refuse a new job that would make retained dispatched history reach 64, or consume the last required registration/journal/byte headroom; do this before creating a doomed Core queued job where possible. Template slots mean registration capacity can exhaust before 63 jobs. Duplicate idempotent reads/replays do not spend slots. Host still enforces its own remaining allowance independently; no caller can enlarge it in an RPC. The history validator's 2048-row/16-MiB bound and spool/host byte bounds remain global, not per epoch.

At any exhausted limit return `native_retention_capacity` with the exhausted dimension, used/limit and actionable instruction: retain this owner and all evidence; existing reads remain available where the valid owner is already open; further execution requires a separately implemented retention/archival policy. Do not suggest deleting a journal/spool, creating a fresh deployment to bypass counts, raising caps, or evicting voices. If an already-at-limit history cannot pass existing activation bounds, report maintenance refusal explicitly; this slice does not promise to reopen it through a relaxed bound. Preflight renewal against all cumulative bounds and at least one prospective compatible generation's headroom; otherwise refuse before retirement where knowable. Separate source tests establish predictable refusal; no capacity-reclamation claim.
