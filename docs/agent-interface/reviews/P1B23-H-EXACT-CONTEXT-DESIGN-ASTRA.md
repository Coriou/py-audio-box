## One selected representation

Use two explicitly separate checks in the same future finite construction invocation:

1. **Actual decode:** captured `recovery._run_bounded_maintenance.__code__`, real `dis.get_instructions`, unchanged `_H_exit_literal` and `_H_instruction`, no projection installed. Independently select the source exit statement's CALL, require the fixed positive, scan every actual CALL for exactly that singleton, and check its actual cache interval.
2. **Predicate controls:** immutable records containing exactly the fields consumed by these two unchanged methods: `offset`, `opname`, `argval`. Derive the complete record sequence from that same actual decoded stream; introduce only the enumerated field projections below. Call the real unchanged recognizer, with fixed expectations. Do not copy its boolean expression as the acceptance implementation.

This deliberately tests the decoded-instruction boundary. It does **not** claim that projected records are the disassembly of the carrier's bytes, valid executable programs, alternate compiler output, or live unwinding evidence. In particular, an isolated arity probe keeps the immediate argument path intact while changing CALL's decoded count. A physically lowered zero/two-argument call can move that window and fail owner first; using that as the sole arity control would repeat the wrong-stage problem.

Reject bytecode editing for this task. Even never-executed `CodeType.replace(co_code=...)` fixtures would require an encoder, cache widths, EXTENDED_ARG/name/constant addressing, exception/line tables and stack bookkeeping. Width changes to represent real zero/two-argument calls also defeat isolated arity testing under the intentionally fixed five-slot rule. None of that buys authority: synthetic code still cannot prove the captured live route. A three-field projection plus the independent actual decode is smaller and states its evidence limit honestly.
