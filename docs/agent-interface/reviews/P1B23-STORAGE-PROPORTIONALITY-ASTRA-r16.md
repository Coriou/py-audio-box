## Decision: preserve the requirement, remove the unsupported extra guarantee

1. Physical allocation <=1GiB **including backend metadata**, allocated-inode quota <=200000, and an immutable backend allocation UUID are no longer admission requirements. Ordinary Docker volume identity is recorded honestly; never call its name immutable.

3. Permit preparation before a hard-quota capability exists. Availability of the existing local driver, usable fresh-volume permissions, adequate backing space and exact lifecycle behavior are the actual operational prerequisites.

Keep the no-host-bind choice for this selected path because a local volume avoids host-sharing semantics and host ownership repair. **It is an engineering preference here, not a newly discovered user prohibition.** A canonical private bind could preserve bytes too, but adds host-path and SQLite filesystem-semantic qualification; switching to it is unnecessary. Do not automatically fall back to one after a failed run. No new backend, quota framework, fill campaign, service, privileged host setup or daemon reconfiguration.

The trusted self-hosted boundary matters. We must contain ordinary errors, bounded fixture activity and failed transports. We do not need a new proof against a malicious administrator/daemon. Conversely, trusted input does not make software accounting a hard physical limit: a bug, concurrent disk user, delayed monitor or filesystem failure can exhaust backing storage. State that residual risk plainly. No power-loss, fsync durability, physical ENOSPC or ext4 qualification is obtained merely by choosing a volume.
