# Compatibility commitments 1.0.0

`contracts/v1/legacy-controls.json` is the exhaustive per-control ledger, not just the summary below. It snapshots all 8 app parser surfaces (including positionals, mutually selected controls, parser defaults and default expressions), module constants, environment reads, shared TTS/registry/Redis source identities and four launchers. Source-hash tests force explicit ledger review when implementation changes. Expressions such as DEFAULT_TTS_MODEL resolve through the shared TTS constants snapshot. No app is imported to build the ledger; no models are loaded.

| Existing command/capability | Intended service correspondence | Preserved coverage now and rationale |
| --- | --- | --- |
| voice-synth discovery/list voices/speakers/capabilities | discover, voices_list, voice_get | Unchanged legacy; capability-specific speakers are not invented as supported by new profiles. |
| voice-synth speak clone/built-in, language/style/tone/instruct, sampling, profiles, variants/select-best/chunk/QA/alignment | speech_generate plus future typed advanced settings adapter | Unchanged legacy for **all** controls; initial compact speech request intentionally does not accept advanced keys. Reject unsupported fields, never drop them. |
| register built-in, design/save, rename/delete/export/import voice | voice_design, voice_save, voice_archive where semantics agree | Unchanged legacy. Rename/delete/portable archives retain old semantics; service archive is distinct from deletion. No unsafe ZIP/pickle bridge is implied. |
| voice-clone prepare/speak/migrate-registry/self-test | voice_prepare, speech_generate, migration_preview/apply | Unchanged legacy, including reference selection, prompt prefix/suffix, quality gates, force-bad-ref, model/dtype/timeouts and existing trusted prompt compatibility. New service migration does not call legacy in-place migration. |
| voice-split local/YouTube, separation, VAD/ASR selection, clip length/count/seed/reference metadata | asset_upload/acquire and later voice_prepare adapter | Unchanged legacy all controls; only restricted YouTube subset is proposed for public acquisition, arbitrary yt-dlp sites are not admitted. |
| voice-register local/URL preparation, selection/quality/registration/test synthesis controls | acquisition/prepare/save, future typed advanced adapter | Unchanged legacy atomic registration, provenance and identity; no automatic test speech or lossy conversion. |
| voice-cpu speak/batch Kokoro/Pocket, preset/reference, assets/language/seed/threads/deadline/report/continue-on-error | speech_generate/blocks_generate with explicit CPU identities | Unchanged legacy; no change from Qwen default. Homogeneous batch residency and parent-owned Pocket reference snapshots remain. |
| audio-export rate/channel/optional loudness | project_render only for the new explicit PCM24 policy | Unchanged legacy including 24/44.1/48/96 kHz and loudness options. Strict new render default does not remove old export choices. |
| job-runner plan/enqueue/enqueue-beats/compile/run/execute-manifest/status/result/report/history/retry/flush/package-status | job_get/cancel/retry and project operations only as new independent service work | Unchanged legacy Redis/YAML/beats/packages/lock/reclaim/QA/alignment workflows. No Redis migration, flush or replay through service. |
| job-watcher scheduling/consumer/once and environment configuration | no new-service scheduler equivalence | Unchanged legacy; service executor has a separate ownership model and cannot steal Redis jobs. |
| run/run-cpu/run-direct/run.ps1 environment and container selection | new client packaging in 0C | Unchanged legacy CPU/GPU/network/elevation/mount selection; new service transport never forwards arbitrary argv. |

Existing Qwen default model is `Qwen/Qwen3-TTS-12Hz-0.6B-Base`; CustomVoice and VoiceDesign defaults remain as snapshotted in lib/tts.py, with language/dtype/profile/sampling defaults unchanged. `speech-economy-v1` is a prospective separately named service preset, not a legacy replacement. Exact voice IDs/aliases/reference bytes/hashes/transcripts/provenance must survive import; synthetic `voice.0` / `legacy_0` exercise allowable punctuation without accessing a private registry.

Promotion from unchanged legacy to service support requires a closed typed settings schema, backend capability checks, frozen identity/default fixtures and adapter tests before updating this ledger. A future consumer cannot interpret this inventory as permission to execute its recorded command strings. Existing internal ASR/QA/alignment remains available; no public STT API is created.
