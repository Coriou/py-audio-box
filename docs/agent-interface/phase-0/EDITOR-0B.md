## Decision and primary sources

Use a thin React/TypeScript timeline plus **WaveSurfer 8.0.2 (BSD-3-Clause)** as a read-only waveform renderer. Canonical project snapshots, revisions, immutable take/asset identities, typed operation requests and undo live in `studio/src/adapter.ts`, outside WaveSurfer. No component-generated state is authoritative. Exact toolchain and direct dependency versions/licenses are in [dependencies.json](editor-0b/dependencies.json); npm lock includes transitive integrity hashes. Node 25.2.1/npm 11.6.2 are UI evaluation pins only, not a service/runtime mandate.

Waveform Playlist was tested first, before building the selected timeline:

- Published unscoped **waveform-playlist 4.3.3**, MIT; registry modification 2022-06-28. Real browser loaded all 31 shared clips, mapping them to **31 component tracks** versus the canonical **2**. It uses seconds and an internal track-per-source representation. Source: `node_modules/waveform-playlist/lib/Playlist.js` load path, including `const gain = info.gain || 1`. Browser `await window.probeZero()` returned **1** after loading gain **0**. This would silently violate the contract without patching or a compensating adapter.
- The probe's AudioContext reported **44,100 Hz**, despite `sampleRate:48000` configuration. This is a device/context observation, not evidence that the source file or canonical ticks changed. Its initialization also required an explicit matching zoom level; the initial failure and correction are recorded.
- The official repository is **not abandoned**: it now documents a materially different modular React API with optional playout adapters and peers. [Official repository](https://github.com/naomiaro/waveform-playlist), [official documentation](https://naomiaro.com/waveform-playlist/), [MIT license](https://github.com/naomiaro/waveform-playlist/blob/main/LICENSE.md). Current scoped registry metadata is recorded separately in `playlist-modular-registry.json`. Those modules were inspected through official documentation, not runtime-qualified. The 4.3.3 findings do **not** establish defects in the modern modular packages.
- Decision cost: adapting the legacy package would require track grouping, zero-gain correction, seconds/tick conversion, revision fencing and identity reconciliation around internal mutations. That is more state ownership than this bounded fixture needs. Retain its reproducible dev-only probe, without adopting its renderer/playout. Modern modular Playlist remains a future alternative, not a silently qualified replacement.

WaveSurfer qualification is deliberately narrower: [official docs](https://wavesurfer.xyz/docs/) describe a waveform/player rather than an editing engine, recommend predecoded peaks for large media, and expose typed APIs. [Official releases](https://github.com/katspaugh/wavesurfer.js/releases) and [BSD license](https://github.com/katspaugh/wavesurfer.js/blob/main/LICENSE) were checked live on 2026-10-16; registry metadata is retained in `wavesurfer-registry.json`. Browser fixtures instantiate/destroy WaveSurfer for visible clips, supply bounded synthetic PCM as peaks with explicit duration, and never ask it to own edits or mix. The 100 fixture initially had **94 canvases for 47 rendered clips**; scroll reached `b99` and `bed99`. No production-length audio or memory benchmark is claimed.

## Implemented boundary and behavior

`studio/` is a runnable Vite fixture, not the whole studio/service. It directly imports both exact production JSON files, the canonical Draft 2020-12 schema and four shared synthetic WAVs. TypeScript resource types derive from the imported fixture; AJV validates every outbound supported operation and resulting project. The adapter ports relevant project relations; tests additionally call the unmodified Python `contracts.validate` and `edit_semantics` oracle on edited histories. No schema fork or new public operation exists.

Implemented controls: script/clip shared selection; fixed keyboard placement (480 ticks, Shift 4,800); numeric trim; midpoint split; overlap indication and staggered placement; zoom; numeric preview cursor; clip gain including zero, clip mute, track mute/solo and linear fades; explicit long/short candidate replacement; saved local history, reload, undo/redo as new revisions; second-writer conflict and reload recovery. Source text retains whitespace/Unicode. Candidate replacement does not mutate takes or assets, and other clip starts remain fixed. No generation, ripple or script reorder control exists.

Synthetic preview reads only the four bounded mono PCM16/48k fixtures, caches by asset ID, mixes placement/gain/mute/solo and exact fade endpoint equations into a Float32 buffer, rejects actual peak >1, and feeds a 48k AudioBuffer. Browser device reported 48k during playback action. This is mechanical preview evidence only: no listening, perceptual quality, timing tolerance, PCM24 export or acoustic acceptance. Waveform display depicts source PCM, while routing state is shown separately.

Local fixture persistence records typed requests and immutable revision snapshots. Reload replays and validates the history. Saving is labelled **Saved locally · no service**; localStorage failures retain the active in-memory state and report the failure. A stale expected revision changes no snapshot. The tab's known revision is stored in sessionStorage: discovering a foreign revision clears its undo cursor. Real multi-tab concurrent writes are not transactional with localStorage; the service must provide atomic CAS. This fixture must not be reused as a production datastore.

## Contract gaps for the shared owner

1. `clip_split_request` has `clip_id`, `at_tick` and one `new_clip_id`, but no explicit fade redistribution fields. The prose requires explicit valid fade redistribution. This fixture **refuses faded splits** with `invalid_request`; users can explicitly clear fades first. It preserves the existing left clip ID and allocates the supplied right ID, the only executable one-new-ID interpretation. If two fresh IDs are intended, the canonical request needs clarification. No contract was changed.
2. `take_select_request` has a single optional `adjusted_clip`; replacement of a block already represented by multiple split clips has no explicit multi-clip mapping. The fixture **refuses that replacement** atomically, instead of inventing mappings or deleting clips. Replacement is demonstrated before splitting.
3. Undo here uses the declared `project_restore` operation against a checked current revision and retained snapshot. A foreign revision requires reload and clears local undo. General field-scoped undo/rebase after foreign edits needs the future service/client policy; no automatic merge is claimed.

These are bounded restrictions, not canonical semantic additions. The shared owner must decide any broader contract before full Phase 5 editing.
