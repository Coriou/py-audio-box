# Lot 0A consumer contract

Contract and fixture revision: **1.2.0**. Baseline: `a25169bd674b38c232e3476a23ede251b99d20e4`. This pack is E1 implementation evidence, awaiting separate review and integration. It implements no service, store, migration executor or renderer.

## Entry points and versioning

- `contracts/v1/schema.json`: JSON Schema Draft 2020-12, canonical `$defs`. Validate a resource with the document plus `$ref: "#/$defs/project"` (or another named definition). Python consumers use `contracts.validate.validate(kind, value)`; structural validation uses jsonschema, relational checks use explicit Python predicates. Browser clients can use a Draft 2020-12 validator and port the documented semantics, with the same fixtures.
- `contracts/v1/operations.json`: intended HTTP method/route, request/response definition, CLI words, MCP tool name, scope, errors and idempotency header for every operation. GET fields map to path placeholders first, remaining fields to query. POST inputs are JSON. These are proposed transport contracts, not implemented routes. Each named POST endpoint has one closed request schema; it cannot execute argv or arbitrary JSON patches.
- `contracts/fixtures/v1`: exact shared editor/renderer inputs, negative cases and expected outcomes. Generate with `python -m contracts.generate`; WAVs are synthetic mono PCM16 at 48 kHz, not model output. `production-30.json` has three speakers, 30 blocks, 31 clips; `production-100.json` has 100 blocks/200 clips. Both include bed overlap and long/short candidate replacement. The original selected impulse take is not replaced by generating either candidate.
- `contracts/v1/legacy-controls.json`: exhaustive AST inventory of every existing app's parser arguments/subcommands/default expressions, relevant module constants and source hashes, plus launchers. All retain unchanged legacy coverage. This is a compatibility commitment, not a claim that every legacy control is service-supported.

API `/v1` uses contract, persisted fixture and worker protocol revision `1.2.0`. The `v1` directory is the API namespace. This unintegrated correction supersedes prior pack revisions; no deployed data migration is asserted. Future deployed incompatible revisions require explicit migration. Additive changes still update fixtures and consumers deliberately; closed objects intentionally reject unknown controls. IDs are opaque, case-sensitive, permit legacy dots/underscores, and are never synthesized from display names. Text is exact Unicode, including leading/trailing space/newlines; no normalization. Hashes are lowercase SHA-256 of original bytes unless specifically a canonical-request hash.

## Revision, jobs and immutable identity

One expected revision covers an atomic edit. Mismatch returns HTTP 409 `revision_conflict`, current revision and at most 20 changed IDs. No partial write or inference admission occurs. Project creation starts revision 1. Undo/redo/restore are new revisions and preserve intervening history; clients retain the operation they intend to reverse and must conflict-check, never overwrite another client's work. Script reorder is independent of clips.

Every mutating operation carries `Idempotency-Key`, scoped by authenticated principal and operation. The canonical fingerprint is SHA-256 of UTF-8 JSON `[principal, operation, payload]`, sorted object keys, compact separators, unescaped Unicode, finite numbers, no text normalization (see `fingerprint`). Transport key itself is excluded. Payloads here use integers for timing; callers must retain canonical serialized numeric settings rather than change their representation on retry. Same key/hash returns original IDs/receipt; changed hash returns 409 `idempotency_conflict`. Retain this mapping while the job exists; explicit expiry/deletion ends deduplication. Content reuse (`never`/`exact`) is separate. New alternatives use new keys. CLI/HTTP/MCP expose the same stable errors; default messages ≤512 characters, no logs/audio/secrets.

Job graph: queued → running → succeeded|failed; queued/running may request cancel. `cancel_requested` may become succeeded, failed or cancelled. Cancellation is only terminal after confirmed stop/reap; verified completion may win. Terminal states never reopen. An authorized replacement of an interrupted active attempt retains the stored plan/hash after owner death and reap; a retry after terminal failure creates a new job with explicit lineage. Resolution/profile changes always require a newly authorized resolved job. Default heavy attempt budget is one. Client disconnect is not cancellation.

Each attempt has an owner and monotonically increasing generation. Worker messages carry job/attempt/generation/input fingerprint and only managed input IDs/staging ID. Old generations cannot progress or publish. Control owns DB, admission, reconciliation and publication; workers never access DB or managed publication roots. `publication` assumes its `present_hashes` argument was computed by control after actual hash/media verification; presence alone in JSON is not verification. Attempt staging is private, owner-scoped, and deleted only after reap. Unreapable owners quarantine the lane. Preserve Pocket parent-owned 0700 reference snapshots and existing Qwen stop/reap/serialization semantics.

Adopt required immutable bytes, then commit references and terminal success. Those actions are not jointly atomic; reconcile orphan adoption and interrupted commits on restart. Establish owner death and fence before retry. Never publish a success referencing missing media. A worker `result` is a proposal, not publication. Preserve immutable assets, voice versions, take text/settings/reference identity and artifacts; changing them creates new IDs. Asset IDs never expose arbitrary filesystem paths. A managed original and every derivative retain source provenance/hash. Unknown legacy provenance is explicitly missing, never invented.

## Timeline and render semantics

Time is integer ticks at 48,000/second, within JavaScript safe integers. Convert seconds with decimal round-half-up. Ranges are `[in_tick,out_tick)`, nonempty, source-bounded; start ≥0. Clip duration is out−in, end is start+duration, checked for overflow. Original bytes remain unchanged; resampling creates an explicit hashed derivative. A clip points to a managed asset; take clips must agree with that take's audio. Missing media fails, including muted placeholders: it never disappears silently.

Fixed placement is default. Text edits mark dependent takes stale (text or speaker voice-version changed), start zero inference and retain playable old clips. Settings changes likewise invalidate takes when their settings hash differs from the requested generation settings; settings hashes are frozen per take. Generation only adds candidates. Selecting a take is an explicit revisioned edit. A longer replacement leaves following starts unchanged and exposes overlap. A shorter replacement beyond trim bounds fails atomically unless an explicit adjusted clip is supplied. No late result auto-selects itself. Initial assembly is explicit, in named block order, with explicit gap. Ripple names track, end-exclusive start range, anchor, signed delta and exact affected clip IDs; unknown/missing/extra IDs, negative starts or overflow fail. `ripple` validates membership; consumer applies the delta atomically. Split at an interior source tick produces two new contiguous ranges at corresponding project offsets, preserving total length, gain and media identity; fades must be explicitly redistributed to valid bounds.

Render freezes the exact project revision, assets, historical voice versions, operation-specific renderer identity/profile and policy into the job input hash. Per-take TTS identities remain source provenance; the renderer does not claim one TTS model generated all media. Editing the draft cannot alter it. Default 48 kHz PCM24 WAV, mono or stereo; no hidden normalization/ducking/limiting. Stereo→mono averages L/R; mono→stereo duplicates; stereo→stereo preserves channels. Mix sums linear sample amplitudes after gains; track mute, clip mute, then track solo filtering determines audible clips. Gain zero is silence. Clip fades are linear and non-overlapping: a fade of N samples uses multiplier i/N for i=0..N−1 at the beginning, and (N−1−i)/N at the end; N=0 applies unity. Trim precedes fade; overlap sums, gaps fill zeros. Exact length is policy.length_ticks samples at 48 kHz. Over-range absolute final mix >1 fails `clipping`; conversion rounds half away from zero to signed PCM24 with positive full scale capped at 8388607, negative at −8388608. Preview uses identical placement/gains/fades and flags clipping; browser playback tolerance is a separate future measurement.

Selected stale takes require `include_stale=true`. Full render policy must cover all clips. Partial export needs a future explicit selection/omission contract and is rejected by this initial pack (`partial_requires_selection`); it is not silently truncated. No codecs beyond PCM24 are implied. The `renderable` peak argument must come from a future actual mixer, not guessed metadata.

## Profiles and worker boundary

Discovery is cached metadata only: no ML imports, weight loads, network calls or downloads. Support (`unqualified|qualified|unsupported`), install, configuration, readiness and verification states are separate. Qualified requires measured evidence and a receipt; ready also requires installed/valid. Synthetic profile ceilings are finite engineering examples, **not measured hardware support or RAM promises**: CPU 1 expensive slot, accelerators 2, 1 resident model, 2 threads, 32 queued, 16 MiB upload, 600 seconds decoded media/deadline, 10k characters, 4 variants, 1 GiB managed disk quota. Example RAM/VRAM budgets are admission settings pending inventory, not evidence a model fits. All three fixture profiles are unqualified/not-ready. No remote machine specs or STT measurements are inferred.

CPU/CUDA use a networkless worker container, read-only assets, writable private staging and private Unix-socket IPC on a dedicated volume. Control/UI is separate; provision helper alone fetches bounded pinned bundles and atomically activates after verification. No Docker socket or credentials in worker. CPU starts one host-wide expensive lane (decode/render/provision/inference compete), one resident configuration, FIFO, idle-only unload. Qualified stronger profiles may raise ceilings independently. Admission must enforce every configured ceiling before work and during byte/duration/deadline-sensitive processing.

Metal is an optional packaged native companion using scoped authenticated local transport, explicit asset transfer and host-native staging IDs; Linux paths are never assumed to exist on macOS. Native process isolation/network properties are distinct from networkless containers. Companion absence/disconnect makes readiness false; no automatic reroute. Qualification records exact hardware/ISA/VM/runtime/backend/model/operators/precision/transport and stop/reap/recovery receipts. The pack does not certify any Metal backend.

Requested/effective engine/model/bundle/device/precision are retained in takes, plans and artifacts. `auto` chooses only installed qualified compatible profiles under operator budgets and never downloads. Explicit device absence fails `not_ready` unless CPU fallback was declared; fallback requires visible reason and cannot change engine/model/bundle/voice/quality settings. Explicit precision cannot silently change. A service implementation must consult capabilities as well as validate a resolution structurally; a synthetic identity does not authorize admission.

## Acquisition boundary

Supported intended sources: upload, secure-context microphone, direct public HTTPS media, and YouTube hosted-media acquisition through a restricted adapter around existing voice-split. YouTube watch/youtu.be identifiers only, not all sites supported by yt-dlp. Structural URL patterns are not SSRF protection. Consumer must reject userinfo, secrets, arbitrary sites, private/link-local/metadata/loopback destinations, revalidate DNS and every redirect, cap redirects (3), bytes (profile upload ceiling), time (profile deadline) and decoded duration. No per-request private-source bypass; only explicit installation policy can name a private source. Isolate decoding. No remote pickle or untrusted prompt deserialization. Internal transcription/QA/alignment remains legacy; no new public STT/dictation operations.

## Oracle diagnostics and adapter errors

`ContractError` messages are precise offline invariant diagnostics (for example `invalid_trim`, `implicit_selection`), not a second public error vocabulary. Adapters map invalid structure/relations/forbidden implicit edits to `invalid_request` with bounded field/action; map domain conflicts to the matching stable code in `contracts/v1/errors.json`. That file fixes HTTP status, CLI exit category and MCP error envelope. Structural operation examples in `operation-requests.json` are conformance examples, not pre-authorized submissions: contextual existence, media verification, revision and profile admission checks still apply. `edit_semantics` rejects implicit arrangement/selection on before/after snapshots; it is an oracle for consumer tests, not an editing service.

Block `settings_sha256` is the current explicitly chosen generation-settings identity. A take with a different settings hash is stale alongside changed text/voice version. Adding candidate takes cannot alter selection, existing take identity or arrangement. Block/track deletion must be dependency-aware: reject dangling selected takes, speakers or clips rather than silently discarding shared media. New block bulk edits are capped at 100 per atomic request; larger clients batch with revision checks.

## Transport and resource workflows

All current pack schemas, fixtures and worker protocol are 1.2.0. Consumers import the same schema and `contracts.validate` entry points. Closed typed schemas remain authoritative; there is no command/argv escape hatch.

Media: `asset_upload` carries actual RFC4648 base64 bytes in `content_base64` (HTTP JSON, CLI `asset upload` reads local file and encodes, MCP `speech_asset_upload` uses the same field). Decode strictly, cap decoded bytes at 16 MiB and encoded length before allocation, compare exact decoded length and SHA256 before admission. The principal/operation idempotency fingerprint includes the bytes and provenance; changed bytes conflict. Interrupted JSON uploads admit nothing; retry the same key/body. The existing receipt resolves through job/artifact asset IDs. `asset_content` is the authenticated bounded download operation for both source and artifact assets: HTTP GET query `start,end_exclusive`, CLI `asset content --start --end-exclusive` decodes to stdout/file, MCP returns the typed base64 result. End-exclusive explicit ranges are mandatory; empty, reversed, out-of-file or over-limit ranges fail invalid_request. HTTP returns 200 JSON with explicit range/total/full-content hash, not HTTP Range/206; adapters must not invent a second Range grammar. Full download uses [0,total_bytes), splitting into bounded chunks when necessary. Authorization applies on each chunk; no bearer links. Reassembled bytes must match the full SHA256. `artifact_get` asset_ids followed by `asset_content` is the deliverable path.

Voice get includes numeric revision (0 denotes a reserved new identity; new save uses expected_revision 0 and existing IDs conflict). Prepare/design receipts lead to job_get until success then voice_results by job ID; immutable candidates contain audition asset and complete prospective voice_version. Save consumes that candidate ID atomically against the voice revision, creates a new immutable version ID and increments revision; repeated identical idempotency returns original receipt. Job artifacts retain saved version ID through the voice's version_ids; voice_version_get reads any historical version. Archive increments revision without deleting versions. Failed/cancelled jobs have no saveable candidates. Candidate IDs/results survive reconnect; disconnected clients re-read voice revision and never silently retry a stale save. Candidate versions are prospective: save allocates a new immutable version ID, preserving lineage/content. Concurrent saves with the same expected revision yield one success and one revision_conflict.

History returns bounded numeric revisions with recorded typed edit request and immutable project snapshot; revision_get retrieves one revision. Restore uses that numeric source_revision plus expected current revision, creates a new revision, and never erases intervening history. Recorded requests are audit/undo inputs, not authority to replay stale preconditions. Reconnect reads current revision/history; scoped undo uses a fresh typed edit and conflicts if another writer intervened. History pagination is stable over the captured revision ceiling; next_cursor is opaque and principal scoped.

Worker execution transfers the complete closed worker_plan inline on every message: typed operation/request, resolved execution, exact required asset metadata, and immutable voice-version snapshots. Only render carries a project snapshot; other operations carry null. No database or plan-fetch side channel is needed; asset bytes use managed-ID authorized content transfer. The control-approved resolution inside the stored plan is authoritative; exact text, versions, composition/render policy and all settings are frozen. SHA256 is over UTF-8 sorted-key compact JSON of the entire plan (`plan_hash`); control stores it in job.input_sha256. Reconnect transfers the identical plan, never mutable current project state. Plans are immutable and bounded by admission profile ceilings before serialization; no execution from hash/IDs alone. Only the four declared heavy operations are executable.

`worker_message(message, authoritative_job, allowed_assets, transport_owner=..., context=..., current_profiles=...)` validates inbound worker messages; `transport_owner` comes exclusively from authenticated socket peer credentials or scoped companion session bound by control, never a JSON sender claim. Control-to-worker execute/cancel messages require the inverse authenticated control principal and the same stored tuple/plan. Workers cannot nominate owners or generations. The authoritative job supplies ordered attempts and current generation; full job/attempt/generation/input/staging/owner tuple must match, including on same-generation results. Publication uses this same context and authenticated peer, plus a control-verified current result message, manifest and byte hashes. Prior attempts must be reaped. Replacement requires independent owner-death evidence AND confirmed reap, unique attempt/staging IDs and generation exactly old+1; generation never resets on restart. Reconnect to a living owner resumes observation, not a replacement. Unreapable owners quarantine the lane; staging cleanup waits for reap. Cancel/result commits serialize: verified current result may win cancel_requested; once cancelled/failed/succeeded, late publication fails. The contract oracle does not prove OS credentials, stop/reap or durable serialization (later E2).

Intrinsic resolution rules run recursively at every validate entry point, including nested requests/artifacts/takes/messages. Ordinary edits preserve every existing take, asset and voice version byte-for-byte while permitting new IDs; lifecycle deletion is a separate dependency-aware operation, not an ordinary edit. Ripple returns a validated copy and bounds both resulting start and end; failure leaves input unchanged.

## Frozen execution boundary (1.2.0)

Each version contains closed `configuration` and separate historical `origin`. Qwen preset maps its bundle-approved `speaker` to `synthesise_custom_voice`; Kokoro maps `preset` and explicit fr/en to its adapter, including selector-language membership. Qwen clone maps exactly one managed WAV reference, exact transcript and `icl`/`x_vector` to locally built `create_voice_clone_prompt(ref_audio, ref_text, x_vector_only_mode)` then Base synthesis. ICL requires transcript; this bounded x-vector branch requires empty transcript. Pocket maps one WAV and bundle language to `reference`; its transcript stays empty. No remote pickle or serialized tensor is a voice configuration. Prepared outputs are WAV references, never reusable prompt pickles.

Designed versions retain origin `design`, description, source candidate and separate VoiceDesign generation identity in `design_lineage`; reusable execution is Qwen Base clone over the exact realized reference. Speech never invokes VoiceDesign. Other design reuse combinations are rejected in this initial branch. See the support table in RESPONSE-0A-r2.md. Bundle catalogues are trusted control fixtures, keyed by exact engine/model/hash/mode, with selector-language membership and explicit instruction support derived from backend capability metadata. Catalogue descriptors are not worker claims or model downloads. Synthetic catalogues demonstrate E1 relations only.

`resolved` contains an explicit intended Base reuse identity for design (null for other operations), operation kind, requested/effective resolution, immutable profile snapshot, operator fallback, closed effective settings and their canonical hash. Qwen fields are explicit (language, nullable seed, supported sampling/token controls, nullable instruction); clone rejects instruction. Kokoro contains only kind/language. Pocket contains kind/language/nullable seed. Prepare contains conditioning/output WAV format; design contains Qwen controls and exact description as instruction. Render contains only render policy. Unsupported submitted fields reject; no filtering or mutable defaults. Voice version's settings digest must equal speech's actual effective settings digest. The bounded pack requires a new immutable version when changing that saved settings identity. Authored request text remains exact; there is no implicit text transformation.

`canonical_hash(x)` hashes UTF-8 JSON with sorted keys, compact separators, unescaped Unicode and finite numbers. `settings_sha256` hashes exactly `resolved.settings`. `input_sha256` hashes the entire validated plan including resolution, voice configuration, selected metadata and settings. Numeric JSON representations must remain canonical on retry (1 and 1.0 are not interchangeable preimages). Request idempotency fingerprint is separate and returns the previously stored job; a repeat never re-resolves profiles.

A trusted `context` has `plan` and `bundles`, stored by control before dispatch. `stored_context` checks the stored plan against the authoritative job hash and operation. A received rehashed plan cannot update either. Workers duplicate the plan and resolution exactly, on execute/progress/result and all other messages. Deadline equals authoritative job/attempt deadline; an authorized attempt replacement may receive a new deadline while preserving the acoustic plan hash. The same input/owner/staging fencing and reap checks apply on reconnect/retry. New device/precision/profile/configuration requires a new explicitly authorized job, never replacement under the old hash.

Request fallback defaults to forbid for prepare/design. Resolved allow_cpu requires both request and operator permission. An actual device fallback additionally requires CPU destination and nonempty reason and preserves engine/model/bundle/voice/settings. Explicit precision cannot change; effective auto rejects. Auto is resolved once. Profile snapshot binds id/config revision/device/topology/limits/exact operation-mode-identity compatibility, excluding volatile checked_at/readiness fields. `admission` compares this snapshot to current trusted profiles and requires qualified/measured receipt, installed/valid/ready; execute messages call admission and reject absent profiles. Busy/quarantined/disconnected states stop new dispatch, never select another profile. Result/publication validates frozen authority without requiring an idle-ready profile: the completing worker may be busy or cancellation pending. All positive hardware admission examples are mocks labelled E1, not real qualification.

`required_asset_ids(plan)` derives inputs from executable fields: prepare source; speech clone/design realization; no media for preset/text-only design; every render clip including muted clips. Render history/take conditioning and unused assets do not grant read access. Plan assets are exactly these dependencies, duplicate-free and metadata-consistent with project copies. Version reference duplication must equal typed configuration at every containing validation entry point. Message input IDs must equal this set, duplicate-free; the independently authenticated control allowlist must cover it. A larger allowlist never grants extra job inputs. `job_input_content` checks active job/attempt/owner, required dependency membership/current ACL, frozen byte SHA256 and explicit byte ranges; runtime still owns actual credential checks, file races and media decoding. Model bundles are separately provisioned resources.

`publication(job, attempt, artifact, present_hashes, transport_owner=..., context=..., manifest=..., verified_result=..., allowed_assets=...)` requires the same stored plan, verified current result message, and a control-verified manifest (not arbitrary worker JSON). Manifest canonical preimage is the complete closed `result_manifest`: operation, job/attempt/generation/owner/staging/input hash, artifact ID, output asset metadata and candidates. Artifact manifest digest equals `canonical_hash(manifest)`. Result IDs and artifact IDs equal exactly the output metadata ID set; outputs are distinct from job input IDs. `present_hashes` is trusted control-computed asset-ID to actual byte-SHA256 evidence, not a global presence flag. Each output hash must match. Non-project revision is exactly 0; render revision is exactly frozen project revision. Artifact resolution equals the stored resolution. Immutable input manifest recovers speech voice/configuration provenance. Prepare/design output candidates map their audition and reusable reference to output IDs, preserve transcript and operation lineage; design generation identity/description and source candidate match the frozen plan. Candidate save/reuse never rerolls. No inference/media decoding is claimed by this oracle.

Four `transcript-*.json` fixtures contain trusted synthetic catalogues/profiles/ACLs, complete plan/job/message/artifact/verified manifest/hash evidence and typed catalogue exchanges. Prepare and design reach candidate/save/version-get, whose saved realization is exercised by speech tests. Render begins with project-get and preserves per-take provenance. Ordinary job/status/artifact receipts are metadata-only. Bytes are opt-in through explicit byte operations; CLI/host adapters upload/transfer/decode outside model context and return compact managed receipts. A direct text-only MCP client must cap each decoded range/upload at 3072 bytes (4096 base64 characters plus bounded metadata), reject larger inline payloads, and direct larger transfers to the existing host/CLI path. Server transport's 16 MiB ceiling is not a model-context budget. Actual client payload/token behavior remains a 0C/1B gate; this is no transfer-platform redesign.
