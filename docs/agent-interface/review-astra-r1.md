NO-GO for treating the current synthesis as a frozen, full implementation specification.** The remaining blockers are technical decisions below, not reasons to reopen the user's confirmed scope. Incorporating these dispositions and making the contract-stage outputs explicit resolves the planning objections; executable schemas and prototype evidence remain outputs of that stage.

Defaults below are reviewer recommendations. None of the proposed token, latency, RAM or hardware budgets is a measured service result. Existing local TTS evidence cannot qualify the new service or its audio workflow.

The reviews correctly identify the important reuse boundary: backend contracts, voice/reference handling, supervised model lifetimes and audio utilities are useful assets. The current queue is substantial but synthesis-specific. Its enqueue Lua does not compare conflicting payloads, its successful-record transaction has no per-attempt publication fence, and local package assembly follows the done/ACK transaction (`lib/jobqueue.py:73`, `apps/job-watcher/job-watcher.py:1031`). Those facts make “a queue rewrite is unnecessary” too categorical. They do not establish that legacy automation is broken within its existing scope.

## B1 — Resolve persistence and migration to one authority

**Disposition: SQLite for the new service; no Redis bridge in v1.** Use one control owner, local durable storage, WAL, `synchronous=FULL`, foreign keys, bounded busy handling and short transactions. Projects/revisions, immutable execution plans, idempotency, job/attempt state, leases/generations, artifacts, events and delivery outbox share one database transaction boundary. Workers never open the database. Network clients access the application service, not a shared DB file. SQLite's documented single-writer and local-filesystem constraints suit this initial topology; this is an architectural recommendation, not a throughput measurement. [SQLite appropriate uses](https://www.sqlite.org/whentouse.html), [WAL and durability](https://www.sqlite.org/wal.html).

The queue implementation is new work, not a free SQL replacement for Redis Streams. Include restart recovery, delayed retries, cancellation, fair admission, fencing and durable outbox in its contract and fault-injection tests. Reuse existing validation and lifecycle lessons without maintaining a second scheduler. A future remote worker claims service-owned jobs through authenticated RPC; it does not acquire an independent Redis authority.

Keep existing CLIs and Redis watcher available as a separate legacy mode, with their old defaults and identifiers. Do not reinterpret old payloads, consume a Redis job into SQLite automatically, or dual-write queue state. Import completed packages and registry data through a dry-run/report/apply migration into a distinct service data root. Retain original bytes, slugs/legacy IDs as aliases, source hashes and original metadata. Stable new voice IDs must survive display-name changes; a slug-directory rename is not the API identity model. Never leave legacy tools and the service concurrently mutating the same registry tree. Drain or leave pending legacy jobs in that mode; migration must report them explicitly. Existing manifests need not claim provenance fields that were never recorded.

Filesystem publication and a SQLite transaction are not jointly atomic. Workers write attempt-owned staging; the control owner validates and adopts immutable content on the same filesystem, then commits the artifact references, successful state and completion event with a current-generation check. A crash may leave unreferenced content, which recovery reconciles. It must not leave a successful job referencing absent required deliverables. No model worker writes the canonical published namespace. Cleanup respects active attempts and referenced originals. Backup uses a consistent DB snapshot plus its referenced immutable files, not a live copy of the main `.db` file alone.

## B2 — Make the image/process/network topology executable

**Disposition: three service roles, selected worker image, no Docker socket.**

1. A small control image serves compiled UI, HTTP, jobs, event/outbox delivery and the metadata store. It imports no ML runtime and is the only metadata writer. Bind the published host port to loopback by default; private-server use supplies HTTPS through a documented reverse proxy.
2. A selected worker image contains a long-lived lightweight supervisor and a model-owning child. Use `network_mode: none` for the packaged local inference profile, Unix-domain-socket IPC on a dedicated volume, read-only model/reference inputs, and a separate writable attempt-staging volume. Authenticate/validate IPC requests and constrain their typed operations. The worker has no public port, DB mount, provider credentials, source checkout or Docker socket.
3. A narrowly scoped fetch/provision helper supplies the UI's explicit model-download and remote-import actions. It has network access and only its staging/model-bundle mounts; it accepts typed requests over private IPC, not arbitrary commands or URLs without policy. It activates immutable versioned bundles only after verification. Networkless decoding/inspection follows fetch. Inference cannot implicitly invoke downloads. A CLI-only one-shot helper is acceptable for early contracts, but the completed v1 UI journey must actually work without requiring the UI to launch Docker.

This resolves a real inconsistency: a worker using ordinary container TCP to poll the API is not equivalent to today's `--network none` CPU execution. An internal Docker network can restrict egress but is a different isolation claim; qualify it separately if selected later. The recommended local profile uses sockets so no such claim is needed.

Start with one global inference slot on the host and one selected resident backend configuration. Qwen remains the existing default; choosing a Kokoro starter profile is an explicit setup choice. Model identity includes engine/checkpoint/device/dtype/runtime settings; conditioning identity additionally includes exact voice/reference version. Do not reload model weights merely for another compatible voice, and do not share incompatible cached conditioning. One bounded render/decode lane can run independently only within a declared host CPU/RAM budget. Resource admission covers provisioning and decoding too.

Default to on-demand model load and an explicit configurable idle-unload policy; five minutes is a prototype starting value, not a latency/RAM promise. Warm reuse must span service jobs, unlike the current watcher subprocess-per-job path. A timeout invalidates that child generation; replacement follows confirmed stop/reap, and an unreapable owner quarantines its lane. Idle eviction cannot interrupt work or publication. Model switching and fairness must not indefinitely starve earlier jobs to preserve cache warmth.

Qualify Linux x86_64 CPU first, then one named Linux/NVIDIA image/device/checkpoint profile. These are release-test priorities, not universal support claims. Do not advertise macOS GPU acceleration, ARM CPU compatibility, minimum VRAM or cloud wake costs without separate evidence. Actual access to the user's preferred acceptance hardware is a human/logistical dependency; the architecture need not wait for it.

## B3 — Freeze the minimum studio and timing semantics

**Disposition: an actual speech arrangement editor, including basic uploaded beds, is v1.** Script blocks/speakers, alternative takes, selected take, waveform clips, non-destructive split/trim/move/reorder, explicit pauses, gain, linear fades, intentional overlaps, multiple audio tracks, track mute/solo, clip mute, play/scrub/zoom, keyboard timing controls, autosave, undo/history and asynchronous render/export are in scope. Imported speech/music/SFX use the same clip model. No effects graph, automation envelopes, MIDI, plugins, video editing or time stretching is required.

Use a fixed **48,000 ticks/second** project timebase, with integer nonnegative positions and end-exclusive ranges. Prepare immutable 48 kHz editor/render derivatives from retained originals under an explicit project ingest policy; record channel conversion/resampling and tool version. Source byte identity remains available. Clip trims address these derivatives, avoiding mixed-rate trim ambiguity. Output presets may resample the finished master. Bound integer values to browser-safe ranges and define round-half-up at timebase conversion; repeated UI edits never round through floating-point seconds.

The draft default is **fixed placement**. A new take becomes a candidate and does not push later clips. Adoption preserves start/trim intent only when valid; shorter incompatible takes require an explicit trim adjustment. A script reorder does not silently rearrange an edited timeline. Provide a separate ripple operation naming the track/range/anchor and affected clip IDs; its full edit batch is revision-checked. First assembly can explicitly lay out blocks sequentially with a declared gap. Splitting a clip creates two references, not two synthesis jobs.

All playable/renderable clips reference immutable derivative assets; ungenerated blocks are explicit placeholders. Default final render rejects unresolved placeholders or missing assets. A user-requested partial render must name its selection and report omitted blocks, never silently substitute silence. Stale audio remains playable with its status; rendering a revision with stale selected takes requires an explicit policy/acknowledgement recorded in the render plan.

Use one composition contract for preview and offline rendering: placement, trims, fades, gains, channel mapping and overlap summation. State the clipping/headroom policy in each output preset; no hidden normalization or automatic ducking. A pinned renderer can have deterministic fixture output, but browser playback need only match timing and gain/fade behavior within declared tolerances, not be byte-identical. Neural generation is not guaranteed deterministic. Default master delivery is PCM24 WAV; a small explicit compressed-delivery preset can be added after codec qualification.

One project revision is the mutation/CAS boundary, with immutable render snapshots. Child block/clip revisions allow precise stale-completion detection. Undo is a new revision, never rewriting history; after reload, revision history remains available even if the ephemeral UI undo stack resets. Candidate-take arrival cannot replace a human selection or overwrite a newer authored text revision. Preserve exact script text and record any synthesis-only transformation separately.

## B4 — Specify authentication and completion without a platform project

**Disposition: same-origin sessions for people, named scoped tokens for API/CLI, stdio MCP bridge as the baseline.** Bootstrap uses a single-use, expiring administrator setup code available only through the host operator path. Setup establishes the administrator credential; subsequent users/agents receive attributable credentials. Store password/token verifiers using maintained security libraries; show new API secrets only at creation. Scopes are read, production-write and admin. Browser sessions use HttpOnly cookies, Secure in HTTPS mode, SameSite and CSRF protection. Validate configured Host/Origin, including localhost against rebinding/cross-origin writes. No long-lived token in query strings, browser local storage or download URLs.

The small local MCP stdio adapter uses its configured scoped HTTP credential and the same public API; it can target the HTTPS private server. This satisfies MCP without forcing an OAuth authorization server into the basic install. Direct remote Streamable HTTP MCP is an optional tested profile that must implement the selected clients' applicable authorization requirements; do not claim arbitrary-bearer compatibility or universal remote-host support.

Use durable job handles, bounded wait/CLI wait, event cursor replay and optional registered signed webhooks. Keep callback delivery status separate from audio success. Admin registers destinations; jobs only select destination IDs. Disable callback redirects; apply address/egress checks to imports and callback destinations, with deliberate admin-only local exceptions. The first supported wake integration is a small runner that maps completion IDs to its own resumable workflow. Do not promise that a webhook or MCP notification wakes an arbitrary agent or conversation.

I independently verified the reported MCP 2026-07-28 release and optional Tasks move against maintainer/specification sources. The ordinary short tool-call/job-handle path remains sufficient; no Tasks, subscriptions extension, serverless routing or protocol-session machinery is a mandatory product dependency. Pin SDK/client versions in the compatibility matrix and recheck at implementation. [MCP release](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [Tasks extension](https://tasks.extensions.modelcontextprotocol.io/specification/2026-07-28/tasks), [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization).

## B5 — Replace contradictory tool counts with a measured contract gate

The proposed eight/nine-tool and 2,000/2,500-token limits are competing hypotheses. **Use the agent-contract report's nine focused families as the initial prototype, not an absolute tool-count cap.** Ensure project creation/rendering, artifact retrieval and bulk status have explicit typed routes; add focused tools when selection accuracy improves. Reject a generic arbitrary command executor or untyped `payload` that moves schema complexity into every conversation. Optional expert controls must not make ordinary speech require model identifiers or sampling settings.

Adopt one provisional budget: essential eager catalogue plus onboarding at most **2,500 model-visible tokens**, compact status at most **1 KiB**, receipt at most **2 KiB**, default lists at most **20 entries**. Measure actual schema/tokenizer/client behavior; changing these targets needs recorded task-success/context evidence, not permission theater. Count structured-content/text duplication and fetched operation schemas. A host that cannot defer schemas must still complete the workflows. Success/recovery and total task cost outrank raw tool count.

`ACCEPTANCE.md` is the correct primary task-level gate. Extend it with the choices here: sole-store crash cases; migration preserving legacy data; socket/networkless topology; missing/stale render inputs; shorter take adoption; split and explicit ripple; authentication/CSRF; backup/restore; and helper provisioning failure. Measure inference starts and model loads separately: a cold task can legitimately load more than one model for a requested clone/design pipeline. The service must not disguise those costs.

## Required contract-stage outputs and final disposition

Before parallel implementation expands, produce checked-in versioned schemas for IDs/revisions, operation envelopes, state transitions, errors and composition; a capability/default matrix; a static API/MCP catalogue fixture with measured tokens; an explicit legacy feature mapping; and an install/storage/network diagram. Then prove one fake-worker vertical slice through submit/restart/claim/publish/event and a synthetic timeline render with browser preview. These are implementation deliverables, not facts established by this review.

All five planning objections above have concrete recommended dispositions. They require no further product-scope permission. Framework and visual identity can be selected during the bounded prototype; they do not block the architectural contract. The remaining genuinely human-dependent matters are product name/visual preference, access to the hardware and agent hosts to certify, and final workflow/acoustic acceptance. Do not turn those later acceptance needs into a reason to postpone the contracts.

After incorporation, the appropriate label is **reviewed plan, ready for contract/prototype stage**. It is neither full implementation specification nor production, runtime, security, listening or visual acceptance.
